## 2. 变更规则

> **⚠️ AI 约束：以下任何一种情况发生时，必须先记录变更，再执行修改。不得先改代码后补记录。**

**必须记录变更的场景：**
- 需求新增、修改或删除
- 技术架构调整（如更换技术栈组件）

## 3. 变更记录

### CR-001: 新增拼团购买功能

| 字段 | 内容 |
|------|------|
| 变更编号 | CR-001 |
| 变更日期 | 2025-07-17 |
| 变更类型 | 需求变更 |
| 影响范围 | 商品管理模块、交易管理模块、新增拼团购买模块 |
| 变更原因 | 用户需求：允许多个用户拼团购买同一商品以获取折扣价，提升平台交易活跃度 |
| 变更内容 | 1. 01-项目概要：核心功能表新增"拼团购买"模块（P1）；验收标准新增拼团相关条目 2. 02-产品需求文档：新增 2.7 拼团购买功能模块（含用户故事、功能描述、AI实现边界、验收条件）；更新 2.2 商品管理增加拼团设置项；新增 BR-04~BR-08 拼团业务规则；新增 GroupBuy 和 GroupBuyMember 数据实体；新增拼团相关界面需求（拼团详情页、我的拼团页）；更新需求优先级矩阵 |
| 影响评估 | 新增独立功能模块，依赖现有用户管理、商品管理和交易管理模块。需新增2张数据表（GroupBuy、GroupBuyMember），新增拼团相关API接口。对现有商品发布流程有小幅改动（增加拼团选项）。不影响已有核心交易流程。 |
| 关联文档更新 | 01-项目概要.md、02-产品需求文档.md |
| 状态 | 已执行 |
