## 2. 新增功能需求：拼团购买

> **⚠️ AI 约束：以下每个功能点都包含明确的"AI 实现边界"，编码时严格遵守。**

### 2.1 拼团购买模块概述

**模块概述：**

拼团购买功能允许卖家为其发布的二手商品设置拼团活动，买家可以发起或参与拼团，当拼团人数在规定时间内达到目标人数时，所有参与者均可以折扣价购买该商品。拼团未成团则自动取消，已支付金额原路退回。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-PT-01 | 作为卖家 | 我希望为商品创建拼团活动（设置拼团价、目标人数、有效期） | 以便通过薄利多销快速出售多件同类商品 |
| US-PT-02 | 作为买家 | 我希望浏览正在进行的拼团活动 | 以便找到价格更优惠的二手商品 |
| US-PT-03 | 作为买家 | 我希望发起一个新的拼团 | 以便邀请其他同学一起拼团购买 |
| US-PT-04 | 作为买家 | 我希望参与一个已有的拼团 | 以便和其他同学一起享受拼团折扣 |
| US-PT-05 | 作为买家 | 我希望查看拼团进度（当前人数/目标人数、剩余时间） | 以便了解拼团是否即将成功 |
| US-PT-06 | 作为买家 | 我希望拼团失败时自动获得全额退款 | 以便没有经济损失 |
| US-PT-07 | 作为买家 | 我希望将拼团链接分享给同学 | 以便更快凑齐拼团人数 |

---

### 2.2 功能详细描述

#### 2.2.1 卖家创建拼团活动

**正常流程：**

1. 卖家在已发布的商品详情页点击"创建拼团活动"
2. 填写拼团信息：
   - **拼团价格**：必须低于商品原价，折扣范围 1折~9.9折
   - **目标人数**：最少 2 人，最多 10 人
   - **拼团有效期**：从拼团发起算起，最短 1 小时，最长 72 小时
   - **拼团库存**：该拼团活动可售总数量（≥ 目标人数）
3. 系统校验参数合法性
4. 创建成功，商品详情页展示拼团标签和拼团价

**异常流程：**

- 商品已下架或库存不足：提示"商品状态异常，无法创建拼团"
- 该商品已有进行中的拼团活动：提示"请等待当前拼团结束后再创建新活动"
- 拼团价格不合理（≥原价或≤0）：提示参数校验错误

#### 2.2.2 买家发起/参与拼团

**正常流程：**

1. 买家在拼团商品页面可选择：
   - **发起拼团**：创建一个新的拼团订单，自动成为团长，支付拼团价格
   - **参与拼团**：选择一个已有且未满的拼团加入，支付拼团价格
2. 支付成功后，订单状态变为"待成团"
3. 系统自动检查拼团是否已满：
   - 已满：拼团成功，所有参团订单状态变为"已成团-待发货"
   - 未满：等待更多用户加入

**异常流程：**

- 拼团已满/已过期：提示"该拼团已结束"
- 用户已参与该拼团：提示"您已参与此拼团，请勿重复参与"
- 支付失败：订单取消，不占用拼团名额

#### 2.2.3 拼团状态管理

**拼团状态流转：**

```
[待拼团] --有人发起--> [拼团中] --人数达标--> [已成团]
                          |
                     有效期到期且人数不足
                          |
                          v
                      [拼团失败] --> 自动退款
```

- **待拼团**：拼团活动已创建，尚无人发起
- **拼团中**：有买家发起拼团，等待凑齐人数
- **已成团**：拼团人数达标，拼团成功
- **拼团失败**：有效期内未达到目标人数，自动关闭

#### 2.2.4 拼团到期处理（定时任务）

1. 系统定时扫描所有"拼团中"的团单
2. 对已过有效期且未满的团单：
   - 将拼团状态置为"拼团失败"
   - 将所有参团订单状态置为"已取消-退款中"
   - 触发退款流程，原路退还支付金额
   - 发送通知告知参团用户拼团失败

#### 2.2.5 拼团分享

1. 团长或参团成员可以生成拼团分享链接/二维码
2. 分享渠道：复制链接、微信分享（如果集成了微信SDK）
3. 其他用户通过链接可直接跳转到拼团详情页参与拼团

---

### 2.3 AI 实现边界

- ✅ 必须实现：
  - 拼团活动的创建、查询、参与完整流程
  - 拼团状态自动管理（成团/失败）
  - 拼团失败自动退款逻辑
  - 拼团列表页和拼团详情页
  - 拼团进度实时展示
  - 拼团分享链接生成
- ❌ 不得实现：
  - 拼团砍价（不同于拼团，砍价是不同机制）
  - 自动成团（凑不够人数系统自动补齐）
  - 跨商品拼团（只能同一商品拼团）
  - 拼团佣金/返利机制
- ⚠️ 需确认后实现：
  - 微信/QQ等社交平台分享集成
  - 拼团排行榜/热门拼团推荐算法

---

### 2.4 验收条件（AC）

- [ ] AC-1：卖家能成功为商品创建拼团活动，设置拼团价、人数、有效期
- [ ] AC-2：买家能发起新拼团并支付拼团价
- [ ] AC-3：买家能参与已有的拼团并支付拼团价
- [ ] AC-4：拼团人数达标后，所有参团订单自动变为"已成团"状态
- [ ] AC-5：拼团到期未满人数时，自动取消并触发退款
- [ ] AC-6：用户不能重复参与同一个拼团
- [ ] AC-7：拼团进度（当前人数/目标人数、倒计时）实时可见
- [ ] AC-8：团长/成员可以生成并分享拼团链接

## 3. 非功能需求（拼团相关补充）

### 3.1 性能要求

| 指标 | 要求 | 备注 |
|------|------|------|
| 拼团状态查询响应 | ≤ 500ms | 高频操作 |
| 参团/支付接口响应 | ≤ 1s | 涉及支付和库存锁定 |
| 定时任务扫描频率 | 每分钟一次 | 拼团到期检测 |
| 拼团并发参团 | 支持 50 人同时参团不出错 | 使用乐观锁或分布式锁 |

### 3.2 安全要求

- 参团操作需校验用户登录状态
- 拼团价格和人数由服务端校验，不信任前端传入
- 防止同一用户通过多账号刷拼团
- 退款操作需有幂等性保证

## 4. 业务规则（拼团相关新增）

> **⚠️ AI 约束：以下业务规则优先级高于 AI 的默认判断。若代码逻辑与业务规则冲突，以业务规则为准。**

| 编号 | 规则名称 | 规则描述 | 适用场景 |
|------|----------|----------|----------|
| BR-PT-01 | 拼团价格约束 | 拼团价格必须 > 0 且 < 商品原价 | 创建拼团活动 |
| BR-PT-02 | 拼团人数约束 | 目标人数最少 2 人，最多 10 人 | 创建拼团活动 |
| BR-PT-03 | 拼团有效期约束 | 有效期最短 1 小时，最长 72 小时 | 创建拼团活动 |
| BR-PT-04 | 不可重复参团 | 同一用户不能重复参与同一拼团 | 参与拼团 |
| BR-PT-05 | 拼团失败退款 | 拼团失败后 24 小时内必须完成退款 | 拼团过期处理 |
| BR-PT-06 | 唯一活动约束 | 同一商品同时只能有一个进行中的拼团活动 | 创建拼团活动 |
| BR-PT-07 | 成团不可取消 | 拼团成功后不可取消拼团（可走正常退货流程） | 成团后 |

## 5. 数据需求（拼团相关新增）

### 5.1 新增核心数据实体

| 实体名称 | 关键属性 | 说明 |
|----------|----------|------|
| 拼团活动 (group_buy_activity) | id, 商品id, 拼团价, 目标人数, 有效时长, 库存, 状态 | 卖家创建的拼团活动定义 |
| 拼团单 (group_buy_team) | id, 活动id, 团长用户id, 当前人数, 目标人数, 状态, 过期时间 | 一次具体的拼团实例 |
| 拼团参与记录 (group_buy_member) | id, 团单id, 用户id, 订单id, 加入时间, 状态 | 每个参与者的记录 |

### 5.2 数据流向概述

```
卖家创建拼团活动 → group_buy_activity
买家发起拼团 → group_buy_team + group_buy_member + order(待成团)
买家参与拼团 → group_buy_member + order(待成团)
拼团成功 → group_buy_team(已成团) + 所有关联 order(已成团-待发货)
拼团失败 → group_buy_team(拼团失败) + 所有关联 order(已取消) + refund
```

## 6. 界面需求（拼团相关新增）

### 页面：拼团活动列表页

- **用途：** 展示平台所有正在进行中的拼团活动
- **核心元素：** 商品图片、商品名称、原价、拼团价、目标人数、已有拼团进度、剩余时间倒计时
- **关键交互：** 点击进入拼团详情页，支持按价格/剩余时间/折扣力度排序

### 页面：拼团详情页

- **用途：** 展示某个具体拼团的详细信息，供用户参与
- **核心元素：** 商品信息、拼团价、原价对比、当前参团人头像列表、目标人数进度条、倒计时、"立即参团"按钮、"发起新团"按钮、分享按钮
- **关键交互：** 参与拼团触发支付流程，分享按钮生成分享链接/海报

### 页面：我的拼团（用户中心子页面）

- **用途：** 展示用户参与的所有拼团记录
- **核心元素：** 拼团商品信息、拼团状态（拼团中/已成团/拼团失败）、拼团进度、操作按钮
- **关键交互：** 拼团中的可分享邀请；拼团失败的显示退款状态

### 页面：创建拼团活动（卖家）

- **用途：** 卖家为商品设置拼团参数
- **核心元素：** 拼团价格输入、目标人数选择、有效期设置、拼团库存设置
- **关键交互：** 表单校验（价格<原价、人数2-10、有效期1-72h），提交创建
