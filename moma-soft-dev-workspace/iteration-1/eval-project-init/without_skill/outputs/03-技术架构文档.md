## 2. 系统架构概览

### 2.1 架构风格

采用 **前后端分离的单体架构**。前端为 React SPA 应用，后端为 Spring Boot 单体服务。选择理由：

- 项目规模适中（单校园场景），单体架构足以满足性能和可维护性需求
- 前后端分离便于独立开发和部署，团队协作效率高
- Spring Boot 生态成熟，开发效率高，社区支持完善

### 2.3 分层结构

| 层级 | 职责 | 技术实现 |
|------|------|----------|
| 表示层 (Presentation) | 用户界面渲染、用户交互处理 | React + Ant Design |
| 网关层 (Gateway) | 反向代理、静态资源托管、SSL终止 | Nginx |
| 控制器层 (Controller) | 接收请求、参数校验、调用业务逻辑、返回响应 | Spring MVC + WebSocket |
| 业务层 (Service) | 核心业务逻辑实现、事务管理 | Spring Service + Spring Transaction |
| 数据访问层 (Repository) | 数据库 CRUD 操作、数据映射 | MyBatis-Plus |
| 数据存储层 (Storage) | 数据持久化、缓存、文件存储 | MySQL + Redis + 本地文件系统 |

### 3.2 禁止使用的技术

> **⚠️ AI 约束：以下技术明确禁止使用，AI 不得在代码中引入。**

| 技术 | 禁止原因 |
|------|----------|
| JSP / Thymeleaf | 采用前后端分离架构，不使用服务端模板 |
| Hibernate / JPA | 统一使用 MyBatis-Plus，避免 ORM 混用 |
| jQuery | 使用 React 框架，不引入 jQuery |
| Lombok 的 @Data | 避免隐式方法生成，使用明确的 @Getter/@Setter |
| Spring WebFlux | 项目使用传统 Servlet 模型，不使用响应式 |

## 6. 关键技术方案

### 6.1 认证与授权方案

- **认证方式**：JWT (JSON Web Token) + Spring Security
- **Token 生成**：用户登录成功后生成 Access Token（有效期 24 小时）和 Refresh Token（有效期 7 天）
- **Token 存储**：前端存储于 localStorage，请求时通过 `Authorization: Bearer <token>` 头携带
- **Token 校验**：Spring Security Filter 拦截请求，解析 JWT 验证合法性
- **Token 黑名单**：登出时 Token 加入 Redis 黑名单（TTL 设为 Token 剩余有效期）
- **角色权限**：
  - `ROLE_USER`：普通已认证用户
  - `ROLE_ADMIN`：管理员（举报审核、用户管理等）
  - 未认证用户仅可浏览和搜索

### 6.2 数据存储方案

- **主数据库**：MySQL 8.0，存储所有业务数据
- **缓存层**：Redis 7.x
  - 热门商品列表缓存（TTL 5 分钟）
  - 用户在线状态存储
  - JWT 黑名单
  - 邮箱验证码存储（TTL 5 分钟）
  - WebSocket 会话映射
- **文件存储**：本地文件系统（`/uploads/` 目录），按日期分目录存储，Nginx 直接托管静态文件访问

### 6.3 错误处理方案

- **全局异常处理器**：`@RestControllerAdvice` 统一捕获异常
- **业务异常**：自定义 `BusinessException`，携带错误码和错误信息
- **参数校验异常**：使用 `@Valid` + `BindingResult`，统一格式化错误信息
- **日志框架**：SLF4J + Logback，按级别和日期分文件输出
- **错误码体系**：模块编号 + 错误编号（如 `USER_1001` 表示用户模块第一个错误）

### 6.4 缓存策略

- **缓存框架**：Spring Data Redis
- **缓存模式**：Cache Aside Pattern（查询时先查缓存，未命中查数据库并写缓存）
- **缓存粒度**：
  - 商品列表页：按分类 + 排序 + 页码缓存，TTL 5 分钟
  - 商品详情：按 ID 缓存，TTL 10 分钟，更新时主动失效
  - 用户信用评分：按用户 ID 缓存，评价提交时失效

### 6.5 消息通信方案

- **协议**：WebSocket + STOMP（Simple Text Oriented Messaging Protocol）
- **实现**：Spring WebSocket + SockJS（兼容不支持 WebSocket 的浏览器）
- **消息路由**：
  - 聊天消息：`/app/chat.send` → `/topic/conversation/{id}`
  - 系统通知：`/topic/notification/{userId}`
- **消息持久化**：所有聊天消息存储到 MySQL，通知消息存储到 notification 表
- **在线状态**：Redis 维护用户在线状态 Set，WebSocket 连接/断开时更新

### 6.6 文件存储方案

- **上传方式**：前端通过 `multipart/form-data` 上传到后端接口
- **存储路径**：`/uploads/{type}/{yyyy}/{MM}/{dd}/{uuid}.{ext}`（type: avatar/product）
- **文件校验**：
  - 允许格式：jpg, jpeg, png, webp
  - 单文件大小限制：5MB
  - 商品图片数量限制：1-9 张
- **图片处理**：生成缩略图（列表展示用），原图保留（详情页展示用）
- **访问方式**：Nginx 直接托管 `/uploads/` 目录，返回静态文件
