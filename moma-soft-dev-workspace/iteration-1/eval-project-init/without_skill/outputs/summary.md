# 项目初始化总结 (Summary)

## 项目概述

根据用户需求"校园二手交易平台"，基于 `simple-software` 模板体系，生成了完整的 8 份项目文档。

## 生成的文档清单

| 文档 | 文件名 | 核心内容 |
|------|--------|----------|
| 项目概要 | `01-项目概要.md` | 项目背景、目标、范围、技术倾向（React + Spring Boot）、验收标准 |
| 产品需求文档 | `02-产品需求文档.md` | 9 个功能模块的详细需求（用户认证、商品管理、搜索、聊天、交易、个人中心、评价、举报、通知），含用户故事、实现边界、验收条件 |
| 技术架构文档 | `03-技术架构文档.md` | 前后端分离单体架构，React 18 + TypeScript + Vite（前端），Spring Boot 3.2 + MyBatis-Plus + MySQL 8 + Redis（后端），WebSocket 实时聊天，Docker 部署 |
| 数据模型文档 | `04-数据模型文档.md` | 11 张数据表设计（user、product、product_image、conversation、message、trade_order、pickup_point、review、favorite、report、notification），含 ER 图、索引、枚举、状态流转 |

| 开发规约 | `06-开发规约.md` | 命名规范、分层架构约束、错误处理、安全编码红线、Git 分支策略、AI 编码专项约束（10 条禁止行为 + 7 条必须行为） |
| 测试策略 | `07-测试策略.md` | 三层测试体系（单元/集成/E2E），6 个模块共 40+ 测试用例，性能测试指标，安全测试清单 |
| 变更日志 | `08-变更日志.md` | 变更规则、初始变更记录、V1.0 版本发布计划 |

## 工作方法

1. **参考模板**：读取了 `simple-software/` 下全部 8 个模板文件，理解其结构、占位符标记（`{{变量}}`、`<!-- AI_FILL -->`）和 AI 约束规则
2. **填充内容**：根据用户需求（校园二手交易 + 学生认证 + 聊天议价 + 校内自提 + React + Spring Boot），将模板中的占位符替换为具体的项目内容
3. **保持一致性**：确保 8 份文档之间的数据实体、接口定义、状态枚举、模块划分等完全一致、相互引用正确

## 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 架构风格 | 前后端分离单体 | 项目规模适中，单体架构足够且开发效率高 |
| ORM | MyBatis-Plus | 比 JPA/Hibernate 更灵活，SQL 可控 |
| 聊天方案 | WebSocket + STOMP | Spring 原生支持，SockJS 提供降级兼容 |
| 状态管理 | Zustand | 比 Redux 轻量，API 更简洁 |
| 文件存储 | 本地文件系统 | V1.0 简单方案，后续可迁移至 OSS |
| 不做在线支付 | 线下面对面交易 | 降低合规风险和开发复杂度 |
