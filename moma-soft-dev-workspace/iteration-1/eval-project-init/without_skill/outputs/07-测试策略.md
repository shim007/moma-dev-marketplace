## 2. 测试范围与策略

### 2.1 测试层次

> **⚠️ AI 约束：AI 生成代码时必须按以下层次同步生成对应测试。**

| 测试层次 | 范围 | 工具 | 覆盖率要求 |
|----------|------|------|------------|
| 单元测试 | Service 层方法、工具函数 | JUnit 5 + Mockito（后端）、Vitest（前端） | ≥80% |
| 集成测试 | API 接口、数据库操作 | Spring Boot Test + TestContainers | 所有 API 接口 |
| E2E 测试 | 核心用户流程 | Playwright | 核心流程覆盖 |

### 2.2 测试优先级

| 优先级 | 测试范围 | 理由 |
|--------|----------|------|
| P0 | 用户注册登录、商品发布、交易流程 | 影响核心功能，必须优先保障 |
| P1 | 聊天消息收发、评价系统、商品搜索 | 影响关键用户体验 |
| P2 | 通知、收藏、举报、管理后台 | 辅助功能，影响较小 |

## 3. 测试用例设计

### 3.1 用户注册与认证

**关联需求：** 2.1 用户注册与学生认证

| 用例编号 | 测试场景 | 测试类型 | 前置条件 | 操作步骤 | 预期结果 |
|----------|----------|----------|----------|----------|----------|
| TC-AUTH-01 | 使用有效 edu.cn 邮箱注册 | 正向 | 邮箱未注册 | 发送验证码→输入正确验证码→填写注册信息→提交 | 注册成功，用户状态为已认证 |

| TC-AUTH-05 | 密码格式不符合要求 | 边界 | 无 | 输入纯数字/纯字母/少于8位密码 | 返回 USER_1003 错误 |

| TC-AUTH-07 | 错误密码登录 | 反向 | 用户已注册 | 输入正确邮箱和错误密码 | 返回 401 错误 |

| TC-AUTH-09 | Token 过期后访问 | 异常 | Token 已过期 | 使用过期 Token 访问受保护接口 | 返回 401 |
| TC-AUTH-10 | 登出后使用旧 Token | 异常 | 用户已登出 | 使用登出前的 Token 访问 | 返回 401 |

## 4. 非功能测试

### 4.1 性能测试场景

| 场景 | 目标指标 | 测试方法 |
|------|----------|----------|
| 商品列表查询 | 响应时间 P95 <500ms，支持 500 并发 | JMeter 压测 |
| 商品搜索 | 响应时间 P95 <800ms | JMeter 压测 |
| 聊天消息发送 | 端到端延迟 <1s | WebSocket 压测工具 |
| 图片上传（5MB） | 响应时间 <3s | JMeter 压测 |

### 4.2 安全测试清单

| 测试项 | 测试方法 | 预期结果 |
|--------|----------|----------|
| SQL 注入 | 在搜索/输入字段尝试注入 SQL 语句 | 无法注入，参数化查询生效 |
| XSS 攻击 | 在商品标题/描述中注入脚本 | 输出被转义，脚本不执行 |
| 越权访问 | 使用普通用户 Token 访问管理员接口 | 返回 403 |
| 越权操作 | 编辑/删除他人商品 | 返回 403 |
| 敏感数据泄露 | 检查 API 响应和日志 | 无密码、完整邮箱等敏感数据暴露 |
| 文件上传恶意文件 | 上传伪装为图片的可执行文件 | 文件类型校验拒绝 |
| JWT Token 伪造 | 使用伪造的 JWT Token 访问接口 | 返回 401 |
| 暴力破解密码 | 连续多次使用不同密码登录 | 5 次后账号锁定 |

## 5. 测试数据管理

### 5.1 测试数据策略

- **单元测试**：使用 Mock 数据，不依赖外部服务
- **集成测试**：使用 TestContainers 启动独立 MySQL 和 Redis 容器，测试前初始化数据，测试后清理
- **E2E 测试**：使用专用测试数据库，预置标准测试数据集

### 5.2 Mock 策略

| 依赖 | Mock 方式 | 说明 |
|------|----------|------|
| 邮件服务（SMTP） | Mockito Mock / GreenMail | 单元测试 Mock，集成测试使用 GreenMail |
| Redis | TestContainers Redis | 集成测试使用真实 Redis 容器 |
| MySQL | TestContainers MySQL | 集成测试使用真实 MySQL 容器 |
| 文件系统 | 临时目录 | 测试使用临时目录，测试后清理 |

## 6. 缺陷管理

### 6.1 缺陷分级

| 级别 | 定义 | 处理时限 |
|------|------|----------|
| 致命 | 系统崩溃/数据丢失/安全漏洞 | 立即修复 |
| 严重 | 核心功能不可用（注册、交易、聊天） | 当前迭代内修复 |
| 一般 | 功能异常但有替代方案 | 下个迭代修复 |
| 轻微 | UI 瑕疵/体验优化 | 按优先级排期 |

### 6.2 缺陷记录模板

```markdown
### BUG-{编号}: {缺陷标题}

- **级别：** 致命/严重/一般/轻微
- **发现场景：** {测试用例编号或描述}
- **复现步骤：**
  1.
  2.
  3.
- **预期结果：**
- **实际结果：**
- **修复方案：**
- **状态：** 待修复/修复中/已修复/已验证
```
