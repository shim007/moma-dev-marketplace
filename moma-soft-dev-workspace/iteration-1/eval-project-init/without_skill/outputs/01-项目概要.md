## 2. 项目背景与目标

### 2.1 背景描述

高校学生在毕业、换寝、升级设备等场景下产生大量闲置物品（教材、电子设备、生活用品等），但缺乏高效、可信的校内交易渠道。现有的社交群聊交易方式存在信息碎片化、交易不安全、沟通效率低等问题。本项目旨在打造一个专属校园的二手交易平台，通过学生身份认证建立信任基础，通过在线聊天议价和校内自提降低交易成本，为学生提供安全便捷的闲置物品流转平台。

### 2.2 项目目标

- 目标 1：搭建完整的校园二手交易平台，支持学生发布、浏览、搜索闲置物品
- 目标 2：实现基于学生身份认证（学号/校园邮箱）的用户信任体系，确保平台用户均为在校学生
- 目标 3：提供实时在线聊天功能，支持买卖双方议价沟通，消息送达率 ≥99%
- 目标 4：实现校内自提交易流程，支持自提点选择与交易状态追踪
- 目标 5：平台首页加载时间 ≤2 秒，核心 API 响应时间 ≤500ms

### 2.3 目标用户

| 用户群体 | 特征描述 |
|----------|----------|
| 在校大学生（卖家） | 有闲置物品需要出售，希望快速发布并找到买家 |
| 在校大学生（买家） | 希望以较低价格购买二手物品，偏好校内自提的便捷方式 |
| 平台管理员 | 负责审核用户身份认证、处理举报和违规内容 |

## 3. 项目范围

### 3.1 核心功能（必须实现）

| 序号 | 功能模块 | 简要描述 | 优先级 |
|------|----------|----------|--------|
| 1 | 用户注册与学生认证 | 支持注册、登录，通过学号/校园邮箱验证学生身份 | P0 |
| 2 | 商品发布与管理 | 发布闲置物品（图片、描述、价格、分类），编辑/下架商品 | P0 |
| 3 | 商品浏览与搜索 | 首页商品列表、分类筛选、关键词搜索、排序 | P0 |
| 4 | 在线聊天议价 | 买卖双方实时文字聊天，支持发送图片，消息通知 | P0 |
| 5 | 交易管理 | 创建交易订单、选择自提点、确认交易完成 | P0 |
| 6 | 用户个人中心 | 个人信息管理、我的发布、我的购买、收藏列表 | P1 |
| 7 | 评价系统 | 交易完成后买卖双方互评，展示信用评分 | P1 |
| 8 | 举报与内容审核 | 用户举报违规商品/用户，管理员审核处理 | P1 |
| 9 | 消息通知 | 系统通知（交易状态变更、新消息提醒） | P2 |

### 3.2 明确不做的事项

> **⚠️ AI 约束：以下列出的事项，AI 在开发过程中不得实现，不得建议添加。**

- ❌ 不做在线支付功能（交易为线下面对面完成，不集成任何支付系统）
- ❌ 不做物流配送功能（仅支持校内自提，不接入快递物流系统）
- ❌ 不做多校区/多学校联合平台（V1.0 仅面向单一学校）
- ❌ 不做拍卖/竞价模式（仅支持固定价格 + 聊天议价）
- ❌ 不做移动端 App（V1.0 仅做 Web 端，移动端通过响应式适配）
- ❌ 不做商家入驻功能（仅个人学生用户之间的交易）

## 5. 约束与假设

### 5.1 约束条件

- 项目面向单一高校校园环境，用户规模预估为 5000-20000 人
- 学生身份认证依赖学校提供的学号/邮箱系统（假设可通过邮箱验证）
- 不涉及资金流转，所有交易均为线下面对面完成
- 系统需支持主流浏览器（Chrome、Firefox、Safari、Edge 最新两个大版本）

### 5.2 前提假设

- 学校允许学生使用校园邮箱进行平台注册验证
- 用户具备基本的智能手机/电脑浏览器使用能力
- 校园网络环境稳定，能支持 WebSocket 长连接
- 自提点位置由管理员预设，不需要动态定位功能

---

## 6. 验收标准概要

> **AI 约束：AI 开发的最终产出必须满足以下验收标准，作为"完成"的判定依据。**

- [ ] 用户可通过学号/校园邮箱注册并完成身份认证，未认证用户无法发布商品
- [ ] 用户可发布、编辑、下架闲置商品，包含图片上传功能
- [ ] 用户可按分类、关键词搜索和浏览商品列表
- [ ] 买卖双方可通过在线聊天进行实时沟通议价
- [ ] 买家可发起交易、选择自提点，交易双方可确认交易完成
- [ ] 所有 API 接口响应时间 ≤500ms（P95），页面首屏加载 ≤2 秒
