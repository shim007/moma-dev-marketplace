## 2. 功能需求

### 2.1 用户注册与学生认证

**模块概述：** 提供用户注册、登录、登出功能，并通过校园邮箱验证确保用户为在校学生。认证通过后方可使用发布商品等核心功能。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-01-01 | 作为新用户 | 我希望用校园邮箱注册账号 | 以便获得平台使用权限 |
| US-01-02 | 作为注册用户 | 我希望通过邮箱验证码完成学生身份认证 | 以便解锁发布商品等功能 |
| US-01-03 | 作为已认证用户 | 我希望用邮箱和密码登录系统 | 以便使用平台各项功能 |

**功能详细描述：**

1. **注册流程**：用户填写昵称、校园邮箱（格式需匹配 `xxx@xxx.edu.cn`）、密码（8-20位，包含字母和数字），系统发送验证码邮件到校园邮箱，用户输入验证码完成注册。
2. **登录流程**：支持邮箱 + 密码登录，登录成功后返回 JWT Token。连续 5 次密码错误锁定账号 30 分钟。
3. **身份认证**：注册即完成校园邮箱验证，视为通过学生身份认证。认证状态分为：未认证、已认证。
4. **登出流程**：客户端清除 Token，服务端 Token 加入黑名单。

**AI 实现边界：**
- ✅ 必须实现：注册、登录、登出、邮箱验证码、JWT Token 认证
- ❌ 不得实现：第三方登录（微信/QQ）、手机号注册、人脸识别认证
- ⚠️ 需确认后实现：忘记密码/密码重置功能

**验收条件（AC）：**

- [ ] AC-1：用户可使用 edu.cn 邮箱注册，非 edu.cn 邮箱注册时提示错误
- [ ] AC-2：注册时系统发送验证码邮件，用户输入正确验证码后注册成功
- [ ] AC-3：已注册用户可使用邮箱和密码登录，登录后获得 JWT Token
- [ ] AC-4：未认证用户不能发布商品，访问发布接口返回 403

### 2.2 商品发布与管理

**模块概述：** 已认证学生可发布闲置商品信息，包括图片、标题、描述、价格、分类等，并支持编辑和下架操作。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-02-01 | 作为已认证学生 | 我希望发布我的闲置物品信息 | 以便其他同学可以看到并购买 |
| US-02-02 | 作为卖家 | 我希望编辑已发布的商品信息 | 以便修改价格或补充描述 |
| US-02-03 | 作为卖家 | 我希望下架已售出或不想卖的商品 | 以便不再展示给其他用户 |

**功能详细描述：**

1. **发布商品**：填写标题（2-50字）、描述（10-500字）、价格（0.01-99999元）、选择分类（系统预设分类）、上传图片（1-9张，单张≤5MB，支持 jpg/png/webp），选择新旧程度（全新/几乎全新/轻微使用痕迹/明显使用痕迹）。
2. **编辑商品**：仅允许商品状态为"在售"时编辑，可修改标题、描述、价格、图片。
3. **下架商品**：卖家可手动下架商品，下架后商品不在搜索结果和列表中展示。
4. **商品分类**：教材书籍、电子设备、生活用品、服饰鞋包、运动户外、票券卡类、其他。

**AI 实现边界：**
- ✅ 必须实现：发布/编辑/下架商品、图片上传、分类选择
- ❌ 不得实现：视频上传、商品推荐算法、AI 自动定价
- ⚠️ 需确认后实现：商品自动过期下架（如 30 天无更新）

**验收条件（AC）：**

- [ ] AC-1：已认证用户可成功发布商品，包含标题、描述、价格、图片、分类
- [ ] AC-2：图片上传支持 1-9 张，超出数量或大小限制时给出明确提示
- [ ] AC-3：卖家可编辑在售商品的信息，已下架/已交易商品不可编辑
- [ ] AC-4：下架后商品不在搜索和列表中展示

### 2.3 商品浏览与搜索

**模块概述：** 用户可浏览商品列表、按分类筛选、关键词搜索、按条件排序，支持分页加载。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-03-01 | 作为买家 | 我希望浏览最新发布的商品列表 | 以便发现感兴趣的闲置物品 |
| US-03-02 | 作为买家 | 我希望按分类和关键词搜索商品 | 以便快速找到我需要的物品 |
| US-03-03 | 作为买家 | 我希望查看商品详情 | 以便了解物品具体情况后决定是否购买 |

**功能详细描述：**

1. **商品列表**：首页展示最新发布的在售商品，每页 20 条，支持分页/下拉加载更多。展示缩略图、标题、价格、新旧程度、发布时间。
2. **分类筛选**：按预设分类进行筛选，支持多分类组合筛选。
3. **关键词搜索**：支持按标题和描述进行模糊搜索，搜索结果高亮关键词。
4. **排序**：支持按发布时间（最新）、价格（从低到高/从高到低）排序。
5. **商品详情**：展示完整信息（全部图片、标题、描述、价格、新旧程度、分类、发布时间、卖家昵称和信用评分）。

**AI 实现边界：**
- ✅ 必须实现：商品列表分页、分类筛选、关键词搜索、排序、详情页
- ❌ 不得实现：智能推荐、千人千面、地理位置排序
- ⚠️ 需确认后实现：搜索历史记录

**验收条件（AC）：**

- [ ] AC-1：商品列表正确分页展示，支持按分类筛选
- [ ] AC-2：搜索功能可正确匹配标题和描述中的关键词
- [ ] AC-3：排序功能正确按价格/时间排序
- [ ] AC-4：商品详情页展示完整商品信息和卖家信息

### 2.4 在线聊天议价

**模块概述：** 买卖双方可通过平台内置的实时聊天功能进行沟通议价，支持文字和图片消息，保留聊天记录。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-04-01 | 作为买家 | 我希望在商品详情页发起与卖家的聊天 | 以便询问商品详情或议价 |
| US-04-02 | 作为用户 | 我希望实时收发消息 | 以便高效沟通 |
| US-04-03 | 作为用户 | 我希望查看历史聊天记录 | 以便回顾之前的沟通内容 |

**功能详细描述：**

1. **发起聊天**：买家在商品详情页点击"联系卖家"按钮，创建或打开与该卖家关于该商品的聊天会话。
2. **实时消息**：基于 WebSocket 的实时文字消息收发，支持发送图片（≤5MB）。
3. **聊天列表**：用户可查看所有聊天会话列表，按最近消息时间排序，显示未读消息数。
4. **聊天记录**：消息持久化存储，支持历史记录分页加载（每次 50 条）。
5. **在线状态**：显示对方是否在线。
6. **消息通知**：收到新消息时浏览器推送通知（用户授权后）。

**AI 实现边界：**
- ✅ 必须实现：WebSocket 实时聊天、文字和图片消息、聊天列表、历史记录
- ❌ 不得实现：语音/视频通话、消息撤回、阅后即焚、群聊
- ⚠️ 需确认后实现：表情包/快捷短语

**验收条件（AC）：**

- [ ] AC-1：买家可从商品详情页发起与卖家的聊天
- [ ] AC-2：消息在双方之间实时送达，延迟 ≤1 秒
- [ ] AC-3：聊天记录持久化存储，重新打开会话可查看历史消息
- [ ] AC-4：聊天列表正确显示所有会话和未读消息数

### 2.5 交易管理

**模块概述：** 管理商品交易的完整流程，包括发起交易、选择自提点、确认完成等。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-05-01 | 作为买家 | 我希望对感兴趣的商品发起交易 | 以便锁定商品并安排自提 |
| US-05-02 | 作为买卖双方 | 我希望选择校内自提点和时间 | 以便线下交接物品 |
| US-05-03 | 作为买卖双方 | 我希望确认交易完成 | 以便结束交易流程 |

**功能详细描述：**

1. **发起交易**：买家在聊天中协商好价格后，发起交易请求，填写约定价格和自提信息。
2. **卖家确认**：卖家确认交易请求，商品状态变为"交易中"，其他用户无法再对该商品发起交易。
3. **自提点**：从系统预设的校内自提点列表中选择（如校门口、食堂门口、图书馆等），并约定时间。
4. **确认完成**：双方线下交易后，在平台上确认交易完成。需买卖双方都确认后，交易状态变为"已完成"。
5. **取消交易**：交易完成前，任一方可取消交易，商品恢复为"在售"状态。
6. **交易状态**：待确认 → 进行中 → 已完成 / 已取消。

**AI 实现边界：**
- ✅ 必须实现：发起/确认/取消交易、自提点选择、交易状态流转
- ❌ 不得实现：在线支付、物流跟踪、自动退款、保证金
- ⚠️ 需确认后实现：交易超时自动取消

**验收条件（AC）：**

- [ ] AC-1：买家可发起交易请求，卖家可确认或拒绝
- [ ] AC-2：交易发起后商品状态变为"交易中"，不可被其他人购买
- [ ] AC-3：双方确认后交易完成，商品状态变为"已售出"
- [ ] AC-4：取消交易后商品恢复"在售"状态

### 2.7 评价系统

**模块概述：** 交易完成后，买卖双方可互相评价，评价计入用户信用评分。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-07-01 | 作为交易双方 | 我希望交易完成后给对方评价 | 以便帮助其他用户判断对方信誉 |
| US-07-02 | 作为用户 | 我希望查看卖家的评价和信用评分 | 以便决定是否与其交易 |

**功能详细描述：**

1. **评价**：交易完成后，双方可评价对方（好评/中评/差评 + 文字评价 0-200字）。评价时限为交易完成后 7 天，过期未评默认好评。
2. **信用评分**：基于历史评价计算用户信用分（1-5分），展示在用户资料和商品详情中。
3. **评价展示**：用户收到的评价列表公开展示。

**AI 实现边界：**
- ✅ 必须实现：互评功能、信用评分计算、评价展示
- ❌ 不得实现：追评、匿名评价、评价删除/修改
- ⚠️ 需确认后实现：评价举报

**验收条件（AC）：**

- [ ] AC-1：交易完成后双方可提交评价
- [ ] AC-2：信用评分根据评价正确计算并展示
- [ ] AC-3：7 天过期未评自动默认好评

## 3. 非功能需求

### 3.1 性能要求

| 指标 | 要求 | 备注 |
|------|------|------|
| 页面加载时间 | 首屏加载 ≤2 秒 | 基于校园网络环境 |
| API 响应时间 | P95 ≤500ms | 不含文件上传 |
| 并发用户数 | 支持 500 并发在线 | 校园使用高峰期 |
| 数据量级 | 10 万级商品数据 | 预估 2-3 年数据量 |

### 3.2 安全要求

- 用户密码使用 BCrypt 加盐哈希存储
- API 通过 JWT Token 进行认证，Token 有效期 24 小时
- 所有用户输入进行 XSS 过滤和 SQL 注入防护
- 图片上传需校验文件类型和大小，防止恶意文件上传
- 敏感接口（如登录）实施频率限制

### 3.3 兼容性要求

- 支持 Chrome、Firefox、Safari、Edge 最新两个大版本
- 响应式布局适配桌面端（≥1024px）和移动端（≥375px）
- 不强制支持 IE 浏览器

### 3.4 可用性要求

- 系统可用性目标 ≥99%（月度）
- 数据库每日自动备份
- 关键操作（注册、发布、交易）需有操作日志

## 4. 业务规则

> **⚠️ AI 约束：以下业务规则优先级高于 AI 的默认判断。若代码逻辑与业务规则冲突，以业务规则为准。**

| 编号 | 规则名称 | 规则描述 | 适用场景 |
|------|----------|----------|----------|
| BR-01 | 学生认证限制 | 仅通过学生认证的用户才能发布商品和发起交易 | 发布商品、发起交易 |
| BR-02 | 商品状态互斥 | 一个商品在同一时间只能处于一个交易中 | 交易管理 |
| BR-03 | 自卖自买禁止 | 用户不能购买自己发布的商品 | 交易管理 |
| BR-04 | 评价时限 | 交易完成后 7 天内可评价，逾期自动好评 | 评价系统 |
| BR-05 | 评价不可修改 | 评价提交后不可修改或删除 | 评价系统 |
| BR-06 | 商品价格范围 | 商品价格必须在 0.01-99999 元之间 | 商品发布 |
| BR-07 | 邮箱唯一性 | 每个校园邮箱只能注册一个账号 | 用户注册 |
| BR-08 | 封号处理 | 被封号用户的在售商品自动下架，进行中的交易自动取消 | 举报审核 |

## 6. 界面需求（概要）

### 页面：首页

- **用途：** 展示最新商品列表，提供搜索入口
- **核心元素：** 顶部导航栏（Logo、搜索框、消息图标、用户头像）、分类标签栏、商品卡片网格列表、分页/加载更多
- **关键交互：** 点击分类筛选商品、输入关键词搜索、点击商品进入详情

### 页面：商品详情页

- **用途：** 展示商品完整信息，提供交易入口
- **核心元素：** 图片轮播、标题、价格、新旧程度、描述、卖家信息（昵称、信用评分）、"联系卖家"按钮、收藏按钮
- **关键交互：** 图片轮播查看、点击联系卖家进入聊天、收藏/取消收藏

### 页面：发布商品页

- **用途：** 填写商品信息并提交发布
- **核心元素：** 图片上传区域、标题输入框、描述文本区、价格输入、分类选择、新旧程度选择、发布按钮
- **关键交互：** 拖拽/点击上传图片、表单校验、提交发布

### 页面：聊天页

- **用途：** 买卖双方实时沟通
- **核心元素：** 左侧会话列表（未读角标）、右侧聊天窗口（消息气泡、输入框、发送按钮、图片上传）
- **关键交互：** 切换会话、输入发送消息、发送图片、滚动加载历史记录

### 页面：个人中心

- **用途：** 管理个人信息和查看交易记录
- **核心元素：** 用户信息卡片（头像、昵称、信用评分）、Tab 切换（我的发布/我的购买/我的收藏/我的评价）
- **关键交互：** 编辑个人信息、切换 Tab 查看不同列表

### 页面：管理后台

- **用途：** 管理员审核和管理平台内容
- **核心元素：** 侧边栏导航（用户管理、举报管理、自提点管理）、数据列表、操作按钮
- **关键交互：** 查看举报详情、执行审核操作（下架/警告/封号）

## 7. 需求优先级矩阵

| 功能模块 | 优先级 | 依赖关系 | 备注 |
|----------|--------|----------|------|
| 用户注册与学生认证 | P0 | 无 | 所有功能的基础 |

| 在线聊天议价 | P0 | 用户认证、商品发布 | 核心交易沟通手段 |
| 交易管理 | P0 | 聊天、商品发布 | 核心交易流程 |
| 用户个人中心 | P1 | 用户认证 | 用户体验增强 |
| 评价系统 | P1 | 交易管理 | 信任体系建设 |
| 举报与内容审核 | P1 | 用户认证、商品发布 | 平台治理 |
| 消息通知 | P2 | 交易管理、聊天 | 体验优化 |

> **优先级定义：**
> - **P0**：核心功能，必须首先实现，阻塞其他功能
> - **P1**：重要功能，核心流程完成后实现
> - **P2**：增强功能，时间允许时实现
