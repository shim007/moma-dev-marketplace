### 2.1 用户认证模块

**模块概述：**
提供学生用户的注册、登录和学生身份认证功能。通过学号和学校邮箱双重验证确保用户为在校学生，未认证用户仅能浏览商品，不能发布商品或发起交易。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-01-01 | 作为学生 | 我希望使用学号和密码注册账号 | 以便拥有平台身份 |
| US-01-02 | 作为学生 | 我希望通过学校邮箱验证学生身份 | 以便获得发布和交易权限 |
| US-01-03 | 作为学生 | 我希望使用学号和密码登录系统 | 以便使用平台功能 |
| US-01-04 | 作为学生 | 我希望能修改密码和个人信息 | 以便维护账号安全 |

**功能详细描述：**

- **注册流程：** 用户填写学号、密码、昵称，提交注册；系统验证学号格式合法性和唯一性；注册成功后用户状态为"未认证"。
- **身份认证流程：** 用户填写学校邮箱，系统发送验证邮件；用户点击邮件中的验证链接完成认证；认证成功后用户状态变为"已认证"。
- **登录流程：** 使用学号+密码登录；登录成功返回 JWT Token。
- **异常流程：** 学号已存在则提示重复注册；邮箱验证链接 30 分钟过期；连续 5 次登录失败锁定账号 30 分钟。

**AI 实现边界：**
- ✅ 必须实现：注册、登录、邮箱验证、JWT 鉴权、密码加密存储
- ❌ 不得实现：第三方登录（微信、QQ等）、手机号验证、实名认证
- ⚠️ 需确认后实现：找回密码功能

**验收条件（AC）：**

- [ ] AC-1：新用户可使用学号+密码完成注册
- [ ] AC-2：注册用户可通过学校邮箱完成身份认证
- [ ] AC-3：已认证用户可正常登录并获得 JWT Token
- [ ] AC-4：未认证用户无法发布商品和发起交易
- [ ] AC-5：密码使用 BCrypt 加密存储

### 2.2 商品管理模块

**模块概述：**
已认证学生可发布闲置物品信息，包括商品图片、文字描述、价格、分类等，并可对已发布商品进行编辑、下架和删除操作。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-02-01 | 作为卖家 | 我希望发布闲置物品信息 | 以便其他同学看到我的商品 |
| US-02-02 | 作为卖家 | 我希望上传商品图片 | 以便买家直观了解商品状况 |
| US-02-03 | 作为卖家 | 我希望编辑已发布的商品信息 | 以便更新价格或描述 |
| US-02-04 | 作为卖家 | 我希望下架或删除商品 | 以便在商品售出后移除信息 |

**功能详细描述：**

- **发布商品：** 填写标题（5-50字）、描述（10-500字）、价格（>0）、选择分类、上传图片（1-9张，单张≤5MB）、选择成色（全新/几乎全新/轻微使用痕迹/明显使用痕迹）。
- **编辑商品：** 仅商品所有者可编辑，可修改所有字段。
- **下架/上架：** 卖家可手动下架商品，下架后不在列表展示，可重新上架。
- **删除商品：** 软删除，数据保留但不可恢复展示。
- **商品分类：** 数码电子、书籍教材、服饰鞋包、生活用品、运动户外、美妆个护、其他。

**AI 实现边界：**
- ✅ 必须实现：商品 CRUD、图片上传、分类管理、成色选择
- ❌ 不得实现：视频上传、商品推荐算法、AI 图片识别定价
- ⚠️ 需确认后实现：商品举报功能

**验收条件（AC）：**

- [ ] AC-1：已认证用户可成功发布包含图片的商品信息
- [ ] AC-2：商品信息包含标题、描述、价格、分类、成色、图片
- [ ] AC-3：仅商品所有者可编辑、下架、删除自己的商品
- [ ] AC-4：图片上传限制单张≤5MB，最多9张

### 2.4 即时聊天模块

**模块概述：**
已认证用户可与商品卖家发起一对一即时聊天，用于议价沟通和交易细节协商。基于 WebSocket 实现实时消息推送。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-04-01 | 作为买家 | 我希望通过商品详情页发起与卖家的聊天 | 以便咨询商品信息和议价 |
| US-04-02 | 作为用户 | 我希望实时收发消息 | 以便高效沟通 |
| US-04-03 | 作为用户 | 我希望查看历史聊天记录 | 以便回顾之前的沟通内容 |

**功能详细描述：**

- **发起聊天：** 买家从商品详情页点击"联系卖家"发起会话，每个商品每对买卖关系对应一个会话。
- **消息类型：** 支持文本消息（限500字）和图片消息。
- **实时通信：** 使用 WebSocket 实现消息实时推送，支持在线/离线状态感知。
- **离线消息：** 对方离线时消息存储在服务端，上线后推送。
- **聊天列表：** 展示所有会话列表，显示最新消息和未读数量。

**AI 实现边界：**
- ✅ 必须实现：WebSocket 实时通信、文本消息、图片消息、聊天记录持久化、未读消息计数
- ❌ 不得实现：语音消息、视频通话、群聊、消息撤回、阅后即焚
- ⚠️ 需确认后实现：消息通知推送（浏览器通知）

**验收条件（AC）：**

- [ ] AC-1：已认证用户可从商品详情页发起聊天
- [ ] AC-2：消息实时推送，延迟≤1秒
- [ ] AC-3：支持文本和图片消息
- [ ] AC-4：可查看历史聊天记录
- [ ] AC-5：聊天列表展示未读消息数量

### 2.5 交易管理模块

**模块概述：**
管理买卖双方的交易流程，从发起交易到确认完成，包括约定自提地点和时间。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-05-01 | 作为买家 | 我希望对心仪的商品发起交易 | 以便与卖家确定购买意向 |
| US-05-02 | 作为卖家 | 我希望接受或拒绝买家的交易请求 | 以便决定是否出售 |
| US-05-03 | 作为买卖双方 | 我希望约定自提地点和时间 | 以便线下完成交易 |
| US-05-04 | 作为买卖双方 | 我希望确认交易完成 | 以便完结订单 |

**功能详细描述：**

- **发起交易：** 买家在聊天中或商品详情页发起交易请求，填写期望价格。
- **交易确认：** 卖家可接受/拒绝交易请求；接受后双方约定自提信息。
- **自提约定：** 选择校内预设自提点或自定义地点，约定自提时间。
- **交易完成：** 线下自提后，双方在平台确认交易完成。
- **交易取消：** 交易完成前任意一方可取消。
- **交易状态流转：** 待确认 → 已确认(待自提) → 已完成 / 已取消。

**AI 实现边界：**
- ✅ 必须实现：交易发起、确认/拒绝、自提约定、交易完成确认、交易取消
- ❌ 不得实现：在线支付、退款、物流跟踪、自动仲裁
- ⚠️ 需确认后实现：交易纠纷举报

**验收条件（AC）：**

- [ ] AC-1：买家可发起交易请求
- [ ] AC-2：卖家可接受或拒绝交易
- [ ] AC-3：双方可约定自提地点和时间
- [ ] AC-4：交易完成后双方确认，订单状态更新
- [ ] AC-5：交易状态流转正确，不可逆向跳转

### 2.7 评价系统模块

**模块概述：**
交易完成后，买卖双方可对本次交易进行评价，评价结果影响用户信用积分。

**用户故事：**

| 编号 | 角色 | 行为 | 目的 |
|------|------|------|------|
| US-07-01 | 作为用户 | 我希望交易完成后对对方进行评价 | 以便帮助其他用户判断交易对象信誉 |
| US-07-02 | 作为用户 | 我希望查看卖家的历史评价 | 以便判断是否与其交易 |

**功能详细描述：**

- **评价提交：** 交易完成后 7 天内可提交评价，包含评分（1-5星）和文字评价（可选，≤200字）。
- **评价展示：** 用户主页展示历史评价和平均评分。
- **信用积分：** 根据评价评分计算信用积分，展示在个人主页和商品详情中卖家信息处。
- **评价规则：** 每笔交易仅可评价一次，提交后不可修改。

**AI 实现边界：**
- ✅ 必须实现：评价提交、评价展示、信用积分计算
- ❌ 不得实现：评价申诉、评价删除（管理员功能）、追评
- ⚠️ 需确认后实现：匿名评价选项

**验收条件（AC）：**

- [ ] AC-1：交易完成后双方可提交评价（评分+文字）
- [ ] AC-2：用户主页展示信用积分和历史评价
- [ ] AC-3：每笔交易仅可评价一次
- [ ] AC-4：评价在 7 天有效期内提交

## 3. 非功能需求

### 3.1 性能要求

| 指标 | 要求 | 备注 |
|------|------|------|
| 页面加载时间 | 首屏加载 ≤ 3秒 | 普通校园网环境 |
| API 响应时间 | 普通接口 ≤ 500ms，搜索接口 ≤ 1s | P95 指标 |
| 并发用户数 | 支持 500 并发用户 | 单校场景 |
| 数据量级 | 商品数据 10 万级，用户数据 1 万级 | 初期预估 |

### 3.2 安全要求

- 用户密码使用 BCrypt 加盐哈希存储
- 所有 API 接口使用 JWT Token 认证
- 敏感接口（如修改密码）需二次验证
- 用户输入做 XSS 和 SQL 注入防护
- 图片上传校验文件类型和大小
- 接口做速率限制，防止恶意刷接口

### 3.3 兼容性要求

- 支持 Chrome、Firefox、Safari、Edge 最新两个大版本
- 响应式设计，支持 PC（≥1024px）和移动端（≥375px）
- 不需要原生 App，仅 Web 端

### 3.4 可用性要求

- 系统可用性目标 ≥ 99%（非全天候运维，允许维护窗口）
- 数据库每日自动备份
- 关键操作（如交易确认）需有操作确认提示

| BR-01 | 认证前置 | 用户必须完成学生身份认证后才能发布商品和发起交易；未认证用户仅可浏览和搜索 | 商品发布、交易发起 |
| BR-02 | 卖家不可自买 | 卖家不能购买自己发布的商品 | 交易发起 |
| BR-03 | 单一有效交易 | 同一商品同一时间只能有一个进行中的交易 | 交易管理 |
| BR-04 | 评价时效 | 交易完成后 7 天内可提交评价，超期自动关闭评价入口 | 评价提交 |
| BR-05 | 评价不可修改 | 评价提交后不可修改或删除 | 评价管理 |
| BR-06 | 商品软删除 | 商品删除为软删除，相关交易记录和聊天记录保留 | 商品删除 |
| BR-07 | 价格正数 | 商品价格必须为正数，最多两位小数，上限 99999.99 | 商品发布/编辑 |
| BR-08 | 图片限制 | 商品图片至少 1 张，最多 9 张，单张不超过 5MB，仅支持 JPG/PNG/WEBP | 商品发布 |

## 5. 数据需求

### 5.1 核心数据实体

| 实体名称 | 关键属性 | 说明 |
|----------|----------|------|
| 用户(User) | id, 学号, 密码哈希, 昵称, 头像, 邮箱, 认证状态, 信用积分 | 平台核心用户 |
| 商品(Product) | id, 标题, 描述, 价格, 分类, 成色, 状态, 图片列表, 卖家id | 闲置商品信息 |
| 会话(Conversation) | id, 商品id, 买家id, 卖家id, 最新消息 | 聊天会话 |
| 消息(Message) | id, 会话id, 发送者id, 内容, 类型, 发送时间 | 聊天消息 |
| 交易(Trade) | id, 商品id, 买家id, 卖家id, 价格, 状态, 自提地点, 自提时间 | 交易记录 |
| 评价(Review) | id, 交易id, 评价者id, 被评者id, 评分, 内容 | 交易评价 |
| 收藏(Favorite) | id, 用户id, 商品id | 收藏关系 |
| 通知(Notification) | id, 用户id, 类型, 内容, 已读状态 | 系统通知 |
| 自提点(PickupPoint) | id, 名称, 描述 | 预设自提地点 |

### 5.2 数据流向概述

1. **商品发布流：** 用户填写商品信息 → 图片上传至文件存储 → 商品数据入库 → 出现在商品列表
2. **交易流：** 买家发起交易 → 卖家确认 → 约定自提 → 线下交易 → 双方确认完成 → 评价
3. **聊天流：** 买家发起会话 → WebSocket 建立连接 → 实时消息收发 → 消息持久化存储
4. **通知流：** 业务事件触发 → 生成通知记录 → 推送至用户通知列表

## 6. 界面需求（概要）

> 此处仅描述关键页面和交互要求，不做详细 UI 设计。

### 页面：首页（商品列表）

- **用途：** 展示最新发布的商品，提供搜索和筛选入口
- **核心元素：** 顶部搜索栏、分类标签栏、商品卡片网格（缩略图+标题+价格+成色）、分页控件
- **关键交互：** 点击分类标签筛选、输入关键词搜索、点击商品卡片进入详情

### 页面：商品详情

- **用途：** 展示商品完整信息，提供联系卖家和发起交易入口
- **核心元素：** 图片轮播、商品信息（标题/价格/描述/成色/分类）、卖家信息（昵称/信用分）、联系卖家按钮、收藏按钮
- **关键交互：** 点击"联系卖家"跳转聊天、点击"收藏"收藏商品

### 页面：发布商品

- **用途：** 已认证用户发布闲置物品
- **核心元素：** 图片上传区、标题输入、描述输入、价格输入、分类选择、成色选择、发布按钮
- **关键交互：** 图片多选上传、表单校验、发布成功跳转详情页

### 页面：聊天

- **用途：** 买卖双方即时沟通
- **核心元素：** 左侧会话列表（含未读数）、右侧消息区域、消息输入框、发送按钮
- **关键交互：** 切换会话、发送文本/图片消息、实时接收消息

### 页面：个人中心

- **用途：** 管理个人信息和查看交易相关数据
- **核心元素：** 用户信息卡片、我的发布/我的交易/收藏夹标签页、交易列表
- **关键交互：** 切换标签页、点击商品/交易查看详情

### 页面：登录/注册

- **用途：** 用户身份认证入口
- **核心元素：** 学号输入、密码输入、登录/注册切换、身份认证入口
- **关键交互：** 表单校验、登录/注册提交、邮箱验证流程引导

## 7. 需求优先级矩阵

| 功能模块 | 优先级 | 依赖关系 | 备注 |
|----------|--------|----------|------|
| 用户认证模块 | P0 | 无 | 所有功能的基础 |
