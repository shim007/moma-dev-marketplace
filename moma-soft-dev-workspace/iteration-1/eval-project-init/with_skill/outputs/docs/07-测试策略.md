## 2. 测试范围与策略

### 2.1 测试层次

> **⚠️ AI 约束：AI 生成代码时必须按以下层次同步生成对应测试。**

| 测试层次 | 范围 | 工具 | 覆盖率要求 |
|----------|------|------|------------|
| 单元测试 | Service 层业务逻辑、工具类函数、前端 Hooks | 后端：JUnit 5 + Mockito；前端：Vitest + React Testing Library | 后端 Service ≥ 80%；前端核心 Hooks ≥ 70% |
| 集成测试 | Controller 层 API 接口、数据库操作 | 后端：Spring Boot Test + H2 内存数据库 | 核心接口 100% 覆盖 |
| E2E 测试 | 核心用户流程（注册→发布→交易） | 暂不要求自动化，手动测试 | 核心流程手动验证通过 |

### 2.2 测试优先级

| 优先级 | 测试范围 | 理由 |
|--------|----------|------|
| P0 | 用户认证（注册/登录/JWT）、商品发布与查询 | 核心功能，影响所有业务流程 |
| P1 | 交易流程（发起/确认/完成/取消）、聊天消息收发 | 核心业务闭环 |
| P2 | 评价、收藏、通知、个人信息管理 | 辅助功能，影响较小 |

## 3. 测试用例设计

> **⚠️ AI 约束：以下每个功能模块的测试场景是最低要求，AI 不得遗漏。可以补充但不得删减。**

### 3.1 用户认证模块

**关联需求：** US-01-01 ~ US-01-04

| 用例编号 | 测试场景 | 测试类型 | 前置条件 | 操作步骤 | 预期结果 |
|----------|----------|----------|----------|----------|----------|
| TC-AUTH-01 | 正常注册 | 正向 | 学号未被注册 | 提交合法的学号、密码、昵称 | 注册成功，返回用户信息，authStatus=0 |
| TC-AUTH-02 | 重复学号注册 | 反向 | 学号已存在 | 使用已注册学号提交注册 | 返回 409，提示学号已注册 |
| TC-AUTH-03 | 密码格式不合法 | 边界 | 无 | 提交不符合规则的密码（如纯数字、长度不足） | 返回 400，提示密码格式要求 |
| TC-AUTH-04 | 正常登录 | 正向 | 用户已注册 | 提交正确的学号和密码 | 登录成功，返回 JWT Token |
| TC-AUTH-05 | 错误密码登录 | 反向 | 用户已注册 | 提交错误密码 | 返回 401，登录失败计数+1 |
| TC-AUTH-06 | 账号锁定后登录 | 异常 | 连续5次登录失败 | 再次尝试登录 | 返回 403，提示账号已锁定 |
| TC-AUTH-07 | 发送验证邮件 | 正向 | 用户已登录、未认证 | 提交学校邮箱 | 返回成功，邮件发送 |
| TC-AUTH-08 | 确认邮箱验证 | 正向 | 验证邮件已发送 | 使用有效 token 访问验证链接 | 认证成功，authStatus 变为 1 |
| TC-AUTH-09 | 过期验证链接 | 异常 | 验证邮件已发送超过30分钟 | 使用过期 token 访问验证链接 | 返回 400，提示链接已过期 |
| TC-AUTH-10 | Token 刷新 | 正向 | 持有有效 Refresh Token | 提交 Refresh Token | 返回新的 Access Token |

## 4. 非功能测试

### 4.1 性能测试场景

| 场景 | 目标指标 | 测试方法 |
|------|----------|----------|
| 商品列表查询 | 响应时间 < 500ms（500并发） | 手动或使用 JMeter 压测 |
| 商品搜索 | 响应时间 < 1s（500并发） | 手动或使用 JMeter 压测 |
| 聊天消息发送 | 端到端延迟 < 1s | WebSocket 客户端测试 |

### 4.2 安全测试清单

| 测试项 | 测试方法 | 预期结果 |
|--------|----------|----------|
| SQL 注入 | 在搜索关键词和表单字段尝试注入 SQL 语句 | 无法注入，参数化查询生效 |
| XSS 攻击 | 在商品标题/描述/聊天消息中尝试注入脚本 | 输出被转义，脚本不执行 |
| 越权访问 | 使用普通用户 Token 访问他人商品编辑/交易确认接口 | 返回 403 |
| 敏感数据泄露 | 检查 API 响应是否包含 password_hash 字段 | 无敏感数据明文暴露 |
| JWT Token 伪造 | 使用伪造或篡改的 Token 访问接口 | 返回 401 |
| 文件上传漏洞 | 尝试上传 .php/.exe 等非图片文件 | 拒绝上传，返回 400 |
| 未认证用户限制 | 未认证用户尝试发布商品/发起交易 | 返回 403 |

## 5. 测试数据管理

### 5.1 测试数据策略

- **单元测试：** 使用 Mockito Mock 外部依赖，测试数据在测试方法中构造
- **集成测试：** 使用 H2 内存数据库，每个测试类执行前初始化测试数据，执行后回滚
- **测试数据构造：** 使用 Builder 模式或工厂方法创建测试实体，避免硬编码

### 5.2 Mock 策略

| 依赖 | Mock 方式 | 说明 |
|------|----------|------|
| 邮件服务（Spring Mail） | Mockito Mock | 单元/集成测试中 Mock 邮件发送，验证调用参数 |
| 文件存储 | Mockito Mock | Mock 文件保存操作，返回预设 URL |
| Redis | 嵌入式 Redis 或 Mock | 集成测试使用嵌入式 Redis，单元测试使用 Mock |
| WebSocket | Spring Test STOMP Client | 集成测试使用测试客户端验证消息推送 |

## 6. 缺陷管理

### 6.1 缺陷分级

| 级别 | 定义 | 处理时限 |
|------|------|----------|
| 致命 | 系统崩溃/数据丢失/安全漏洞 | 立即修复 |
| 严重 | 核心功能不可用（无法注册/登录/发布商品/交易） | 当前迭代内修复 |
| 一般 | 功能异常但有替代方案（搜索结果不准确、通知延迟） | 下个迭代修复 |
| 轻微 | UI 瑕疵/体验优化（对齐问题、提示文案不准确） | 按优先级排期 |
