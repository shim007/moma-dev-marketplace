## 1 概述

### 1.1 目的

本文档用于记录{{项目名称}}项目在编码实现阶段进行的所有代码审查活动，包括审查过程、发现的问题、处理结果及统计分析。通过系统化的代码审查记录，保障代码质量，促进团队知识共享，并为过程改进提供数据支撑。

### 1.2 适用范围

本文档记录范围包括：

- 功能特性开发的代码审查
- 缺陷修复的代码审查
- 重构代码的审查
- 安全相关的专项代码审查
- 性能相关的专项代码审查

### 1.3 审查流程概述

```
开发完成 → 提交 PR/MR → 自检清单确认 → 分配审查人员 → 代码审查 → 
反馈问题 → 修复验证 → 审查结论 → 合并代码
```

**审查角色说明：**

| 角色 | 职责 |
|------|------|
| 开发者 | 提交代码、完成自检清单、修复审查问题 |
| 审查人员 | 按照审查清单逐项审查、记录问题、验证修复 |
| 技术负责人 | 审查分配、争议仲裁、流程监督 |

### 1.4 问题严重程度定义

| 等级 | 名称 | 定义 | 处理要求 |
|------|------|------|---------|
| P1 | 严重 | 导致系统崩溃、数据丢失、安全漏洞等严重后果 | 必须在合并前修复 |
| P2 | 主要 | 导致功能异常、性能严重下降、违反核心设计原则 | 必须在合并前修复 |
| P3 | 次要 | 代码风格问题、命名不规范、缺少注释等 | 建议在合并前修复，可协商延后 |
| P4 | 建议 | 优化建议、更好的实现方式、知识分享 | 可选择性采纳 |

### 1.5 问题分类定义

| 分类编码 | 分类名称 | 说明 |
|----------|---------|------|
| FUNC | 功能正确性 | 逻辑错误、算法缺陷、边界条件处理不当 |
| SEC | 安全问题 | SQL注入、XSS、越权访问、敏感信息泄露 |
| PERF | 性能问题 | 性能瓶颈、资源泄露、低效算法 |
| ERR | 异常处理 | 异常吞没、异常处理不当、缺少错误处理 |
| STYLE | 代码风格 | 命名不规范、格式不统一、注释缺失 |
| DESIGN | 设计问题 | 违反设计原则、耦合过高、职责不清 |
| TEST | 测试相关 | 缺少测试、测试不充分、测试用例质量差 |
| DOC | 文档问题 | 接口文档缺失、注释与代码不一致 |
| MAINT | 可维护性 | 代码重复、过度复杂、魔法数字 |
| COMPAT | 兼容性 | 接口兼容性、版本兼容性问题 |
