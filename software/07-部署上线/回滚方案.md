## 2 回滚触发条件

### 2.1 关键故障条件

以下任一条件满足时，应立即启动回滚流程：

| 序号 | 触发条件                                       | 严重等级 | 判定标准                           |
| ---- | ---------------------------------------------- | -------- | ---------------------------------- |
| 1    | 核心业务功能完全不可用                         | P0-致命  | 核心交易/查询接口连续失败超过5分钟 |
| 2    | 数据损坏或数据丢失                             | P0-致命  | 发现任何数据不一致或丢失现象       |
| 3    | 安全漏洞暴露                                   | P0-致命  | 发现已被利用或高风险安全漏洞       |
| 4    | 服务启动失败                                   | P1-严重  | 服务多次重启后仍无法正常启动       |

## 3 回滚策略

### 3.1 全量回滚 vs 部分回滚

| 策略类型     | 适用场景                                       | 优点               | 缺点                     |
| ------------ | ---------------------------------------------- | ------------------ | ------------------------ |
| 全量回滚     | 多个组件存在问题或无法定位具体故障组件         | 操作简单，风险低   | 耗时较长，影响范围大     |
| 部分回滚     | 能明确定位故障组件，其他组件运行正常           | 耗时短，影响面小   | 需确认组件间兼容性       |
