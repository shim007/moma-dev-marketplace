## 2 测试策略

### 2.1 测试级别

#### 2.1.1 单元测试

- **目标：** 验证软件最小可测试单元（函数、方法、类）的逻辑正确性
- **执行人：** 开发人员
- **技术方法：** 白盒测试，使用{{单元测试框架}}框架
- **覆盖率要求：** 语句覆盖率 ≥ {{语句覆盖率目标}}%，分支覆盖率 ≥ {{分支覆盖率目标}}%
- **入口准则：**
  - 代码编写完成并通过代码审查
  - 单元测试用例设计完成并通过评审
  - 测试环境搭建完成
- **出口准则：**
  - 所有计划的测试用例已执行
  - 覆盖率达到目标要求
  - 致命和严重级别缺陷全部修复并验证通过
  - 单元测试报告已提交

#### 2.1.2 集成测试

- **目标：** 验证模块间接口交互的正确性和数据传递的完整性
- **执行人：** 测试团队
- **技术方法：** 灰盒测试，采用{{集成策略}}集成策略（自顶向下/自底向上/三明治）
- **入口准则：**
  - 单元测试完成并达到出口准则
  - 集成测试用例设计完成并通过评审
  - 被测模块已集成至测试环境
- **出口准则：**
  - 所有接口测试用例执行完毕
  - 严重及以上缺陷全部修复
  - 一般缺陷修复率 ≥ {{一般缺陷修复率目标}}%
  - 集成测试报告已提交

#### 2.1.3 系统测试

- **目标：** 验证整个系统是否满足需求规格说明书中的所有功能和非功能需求
- **执行人：** 独立测试团队
- **技术方法：** 黑盒测试
- **入口准则：**
  - 集成测试完成并达到出口准则
  - 系统测试用例设计完成并通过评审
  - 系统测试环境搭建完成并验证通过
  - 待测版本通过冒烟测试
- **出口准则：**
  - 需求覆盖率达到100%
  - 测试用例执行率 ≥ {{用例执行率目标}}%
  - 测试用例通过率 ≥ {{用例通过率目标}}%
  - 致命和严重缺陷全部修复
  - 遗留缺陷经评审确认可接受
  - 系统测试报告已提交

#### 2.1.4 验收测试

- **目标：** 确认系统满足业务需求和用户期望，具备上线发布条件
- **执行人：** 用户/业务代表，测试团队协助
- **技术方法：** 基于业务场景的黑盒测试
- **入口准则：**
  - 系统测试完成并达到出口准则
  - 验收测试用例由用户确认
  - 验收测试环境（含真实数据）准备就绪
- **出口准则：**
  - 所有验收标准已满足
  - 用户签署验收确认书
  - 遗留问题清单已记录并达成共识

## 9 缺陷管理流程

### 9.1 缺陷严重级别定义

| 级别 | 名称 | 定义 | 示例 |
| ---- | ---- | ---- | ---- |
| S1 | 致命 | 系统崩溃、数据丢失、核心功能完全不可用，无法通过任何方式规避 | 系统启动失败；数据库数据被错误删除；资金计算出现严重错误 |
| S2 | 严重 | 主要功能异常、数据错误、业务流程中断，影响范围广但有临时解决方案 | 核心业务流程中断；重要报表数据不正确；用户无法登录 |
| S3 | 一般 | 次要功能缺陷、界面显示异常，不影响主要业务操作 | 非核心功能异常；界面排版错误；提示信息不准确 |
| S4 | 轻微 | 建议性问题、界面美观性、文字拼写等轻微问题 | 错别字；对齐不整齐；颜色与设计稿略有差异 |
