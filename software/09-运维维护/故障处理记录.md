## 1 故障管理流程概述

### 1.1 故障严重等级定义

| 等级 | 名称 | 定义 | SLA响应时间 | SLA修复时间 | 通知范围 |
|------|------|------|-----------|-----------|---------|
| P0 | 紧急 | 核心业务完全中断，影响全部用户，造成严重经济损失或数据丢失风险 | 5 分钟 | 1 小时 | 全体运维 + 管理层 + 业务负责人 |
| P1 | 严重 | 核心业务严重受损或部分功能不可用，影响大量用户 | 15 分钟 | 4 小时 | 运维团队 + 运维负责人 + 开发负责人 |
| P2 | 一般 | 非核心功能异常或性能明显下降，影响部分用户体验 | 30 分钟 | 8 小时 | 相关运维人员 + 应用负责人 |
| P3 | 轻微 | 边缘功能异常或轻微性能波动，对用户影响极小 | 2 小时 | 下一工作日 | 相关运维人员 |

### 1.2 故障生命周期

```
发现 → 响应 → 诊断 → 修复 → 恢复 → 复盘
  │       │       │       │       │       │
  │       │       │       │       │       └─ 故障复盘会议，输出改进措施
  │       │       │       │       └─ 验证修复效果，确认业务恢复正常
  │       │       │       └─ 实施修复方案或临时规避措施
  │       │       └─ 定位故障原因，制定修复方案
  │       └─ 确认故障等级，启动应急响应，通知相关方
  └─ 监控告警/用户反馈/巡检发现
```

**各阶段SLA计时说明：**

- **响应时间**：从故障发现（告警触发/接到报告）到有人员确认开始处理的时间
- **修复时间**：从故障发现到业务恢复正常的总时间
- **复盘时间**：P0/P1 故障须在恢复后 {{复盘时限}} 个工作日内完成复盘

### 1.3 升级矩阵

| 超时时长 | P0 操作 | P1 操作 | P2 操作 | P3 操作 |
|---------|---------|---------|---------|---------|
| 超过响应SLA | 自动升级至管理层 | 自动通知运维负责人 | 自动通知应用负责人 | 标记超时 |
| 修复超过1小时 | 启动战时指挥机制 | 升级至管理层 | 通知运维负责人 | - |
| 修复超过4小时 | 上报公司级应急 | 启动战时指挥机制 | 升级至管理层 | 通知运维负责人 |
| 修复超过8小时 | 持续上报 | 上报公司级应急 | 启动战时指挥机制 | 升级至管理层 |

### 1.4 故障通报机制

| 通报类型 | 触发条件 | 通报范围 | 通报方式 | 通报频率 |
|---------|---------|---------|---------|---------|
| 故障初报 | 确认故障发生 | 按等级确定范围 | 即时通讯 + 邮件 | 立即 |
| 故障续报 | 故障处理中 | 同初报范围 | 即时通讯 | 每 {{续报间隔}} 分钟 |
| 故障解除报 | 故障修复恢复 | 同初报范围 | 即时通讯 + 邮件 | 恢复后立即 |
| 故障复盘报 | 复盘完成 | 全体相关人员 | 邮件 | 复盘后一次 |
