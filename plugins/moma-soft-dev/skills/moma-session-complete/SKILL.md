# /moma-session-complete —— 会话归档

将当前会话的全过程进行结构化总结，并保存为 markdown 文档归档，便于后续追溯本次会话做了什么、为什么这么做、产出了什么。

> 共享约定见 `../moma-soft-dev/references/common-conventions.md`。

## 上下文范围

仅加载当前会话的对话历史与本次会话产生/修改的文件清单。不加载 `simple-software/` 模板，不加载与本次会话无关的文档与代码。

## 步骤

1. **确定输出路径**
   - 目标目录：与项目过程文档保持同一根目录，遵循"优先 `dev-docs/`，其次 `docs/`"的查找/创建规则。即：
     - 若已存在 `dev-docs/`，则归档到 `dev-docs/session-records/`（不存在则创建子目录）；
     - 否则归档到 `docs/session-records/`（不存在则创建）。
   - 文件命名：`session-YYYYMMDD-HHmm-<简短主题>.md`，其中时间使用当前时间，`<简短主题>` 使用本次会话的核心主题（kebab-case，英文或拼音）。

2. **总结会话内容**
   按以下结构生成 markdown 文档：

   ```markdown
   # 会话记录：{{简短主题}}

   - **会话时间：** {{开始时间}} ~ {{结束时间}}
   - **触发指令：** {{本次会话涉及的 /moma-* 指令列表}}
   - **关联文档：** {{涉及的 docs/ 文档清单}}

   ## 1. 用户诉求
   简要复述用户在本次会话中提出的核心需求与背景。

   ## 2. 关键决策
   列出会话中做出的关键决策、方案选型、约束选择，及其理由。

   ## 3. 执行过程
   按时间或步骤顺序，概述 AI 的分析、规划、实施与验证过程，避免逐字复述对话。

   ## 4. 产出清单
   - **新增文件：** {{路径列表}}
   - **修改文件：** {{路径列表}}
   - **删除文件：** {{路径列表}}
   - **生成/更新的文档：** {{docs/ 下文件列表}}
   - **代码变更摘要：** {{每项变更一行简述}}

   ## 5. 遗留事项
   列出本次会话未完成、待用户确认或待后续处理的问题。

   ## 6. 后续建议
   给出推荐的下一步操作（例如建议执行的 `/moma-*` 指令）。
   ```

3. **写入文件**
   - 将上述内容写入上一步确定的目录下的 `session-YYYYMMDD-HHmm-<简短主题>.md`（即 `dev-docs/session-records/...` 或 `docs/session-records/...`）。
   - 写入完成后，向用户输出文件路径，确认归档成功。

4. **可选：登记到变更日志**
   - 如果本次会话对项目代码或 01~07 文档有实质性变更，且 `docs/08-变更日志.md` 存在，则在变更日志中追加一条指向本次会话记录的引用。

此指令不修改任何业务代码，也不修改 01~07 文档，仅生成会话归档文件。
