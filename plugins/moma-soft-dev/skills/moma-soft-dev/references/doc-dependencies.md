# 文档间依赖关系

本文件描述项目文档体系中各文档之间的依赖关系，帮助理解变更时需要同步更新哪些下游文档。

## 依赖图

```
01-项目概要
 ├──▶ 02-产品需求文档
 │     ├──▶ 04-数据模型文档（数据需求 → 表结构）
 │     ├──▶ 05-API接口文档（功能需求 → 接口定义）
 │     └──▶ 07-测试策略（功能需求 → 测试用例）
 └──▶ 03-技术架构文档
       ├──▶ 04-数据模型文档（技术选型 → 数据库方案）
       ├──▶ 05-API接口文档（架构风格 → 接口规范）
       └──▶ 06-开发规约（架构约束 → 编码规范）

08-变更日志 ◀── 记录对以上所有文档的变更
```

## 依赖规则

| 上游 → 下游 | 说明 |
|--------------|------|
| 01 → 02 | 项目概要定义范围，需求文档展开细节 |
| 01 → 03 | 项目概要中的技术倾向，指导架构选型 |
| 02 → 04 | 需求中的数据实体，映射为数据库表结构 |
| 02 → 05 | 需求中的功能点，映射为 API 接口 |
| 02 → 07 | 需求中的验收条件，映射为测试用例 |
| 03 → 04 | 技术架构决定数据库类型和存储方案 |
| 03 → 05 | 架构风格决定接口规范（如 RESTful 约定） |
| 03 → 06 | 技术栈决定编码规范（语言风格、框架约定） |
| 08 ← 全部 | 任何文档的变更都必须在变更日志中记录 |

## 变更影响分析

当某个文档发生变更时，需要检查并可能更新以下下游文档：

- **01-项目概要变更：** 影响 02（需求范围）和 03（技术方向）
- **02-产品需求变更：** 影响 04（数据模型）、05（接口定义）、07（测试用例）
- **03-技术架构变更：** 影响 04（存储方案）、05（接口规范）、06（编码规范）
