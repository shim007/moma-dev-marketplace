# /moma-optimize —— 功能优化

对已有需求进行更详细的约束和优化。这通常是细化现有功能的行为边界，而非新增功能。执行流程遵循 `${CLAUDE_PLUGIN_ROOT}/skills/moma-soft-dev/references/change-workflow.md` 的通用变更流程，本文件只声明本指令的判定点与纯重构模式。

> 共享约定见 `${CLAUDE_PLUGIN_ROOT}/skills/moma-soft-dev/references/common-conventions.md`，编码通用约束必须严格遵守。

## 上下文范围

与 `/moma-modify` 相同 —— 加载用户输入 + 01/02 文档 + 受影响的下游文档 + 变更日志 + 相关代码。不加载模板和无关内容。

## 本指令判定点

- **变更类型判定：** 细化已有功能的**行为边界**（如超时时间、保留时长、校验阈值、边界条件），不新增功能、不改变需求范围——区别于 `/moma-modify`（调整需求本身）与 `/moma-new`（新增功能）。
- **纯重构模式：** 当用户明确本次为纯代码重构（外部行为与需求均不变，如调整内部结构、消除重复、重命名、拆分模块）时：
  1. **跳过 change-workflow.md 步骤3 的文档更新**（01~07 一律不动）；
  2. 步骤5 在 08-变更日志中仍需登记（追加式写入，条目含会话 ID），变更类型注明"技术变更（纯重构，无文档变更）"，并简述重构动机与范围；
  3. 重构必须保持既有测试全部通过；项目无测试时，先建议 `/moma-test` 补齐关键测试再重构，或在报告中明确提示回归风险；
  4. 其余步骤（登记、检查点、范围提交、收尾）照常执行，提交前缀仍为 `optimize:`。

## 步骤

按 `change-workflow.md` 的步骤1~7 顺序执行（纯重构模式按上文跳过步骤3），本指令的差异点：

- 步骤2 意图分析：识别用户输入中哪些**需求细节/行为边界**需要细化，或确认本次为纯重构；
- 步骤6 提交前缀：`optimize: <优化简述>`。
