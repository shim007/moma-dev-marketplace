# /moma-release —— 版本发布

聚合变更记录，产出一个可发布的版本：发布说明 + 版本号 + release 提交 + tag。

> 共享约定见 `${CLAUDE_PLUGIN_ROOT}/skills/moma-soft-dev/references/common-conventions.md`。本文件中 `docs/` 路径均遵循共享约定的 `dev-docs/` 优先规则。

## 上下文范围

加载 `docs/08-变更日志.md` + `docs/09-BUG记录.md` + git 提交历史（自上一个 tag 起）+ 项目版本号载体文件（如 `package.json`、`pyproject.toml`、`pom.xml`、`version.py` 等）。不加载插件内置模板，不加载与版本无关的文档章节。

## 步骤

1. **登记与检查点**
   - 按"多会话并行规约"生成会话 ID，读取花名册 `<docs-root>/.moma-state/roster.md`（不存在则创建）：工作范围声明为 `<docs-root>/releases/` + 项目版本号载体文件 + `08-变更日志.md`（仅追加发布标记条目）。若与其他"进行中"会话的工作范围重叠，拒绝直接执行并报告冲突，按"规则6：worktree 兜底隔离"提议迁移，获用户确认后在 worktree 内执行；否则调整范围或等待。若无重叠，登记本会话条目（状态"进行中"）。
   - 若工作区存在未提交改动，先按规则5生成 `checkpoint:` 提交。
2. **前置检查**：
   - 项目必须是 git 仓库；否则降级为"仅生成发布说明、不提交不打 tag"，并提示用户先初始化版本控制；
   - 按共享约定"文档预检规则"检查 08：文档体系缺失时提示先 `/moma-sync`；
   - 统计上一个 tag（无 tag 则为仓库起点）以来的 08 CR 条目、09 缺陷条目与提交记录；若没有任何变更，报告"无可发布内容"并中止。
3. **版本号决策**：
   - 用户已指定版本号则直接使用；
   - 未指定则按语义化版本推荐：含新功能（`feat:` 提交或新增类 CR）→ 次版本（minor）；仅修复与优化（`bug:`/`modify:`/`optimize:`）→ 修订号（patch）；条目或提交中存在破坏性变更说明 → 主版本（major）。
   - 将推荐版本号与依据呈现给用户，**获确认后**继续。
4. **聚合变更内容**：将上述条目归类为：新增功能 / 优化与调整 / 缺陷修复（引用 BUG 编号）/ 已知问题（09 中未关闭的缺陷）。
5. **生成发布说明**：在 `<docs-root>/releases/`（不存在则创建）新建 `vX.Y.Z-发布说明.md`，使用文末模板。
   > 设计说明：发布说明不写入 `08-变更日志.md` 的"版本发布记录"章节——那会违反规则4的追加式写入约定；08 中仅以步骤7的追加条目作为发布标记并指向本文件。
6. **更新版本号**：按技术栈更新工程版本号载体文件（如 `package.json` 的 `version` 字段）。**不修改 01~07 文档**（保持文档单写者语义）；若 01 中有版本号字段，提醒用户后续通过 `/moma-modify` 同步。
7. **登记发布标记**：按追加式写入规则在 `docs/08-变更日志.md` 末尾追加一条 CR 条目（编号取当前最大编号加 1，条目含会话 ID）：变更类型"版本发布"，内容为"发布 vX.Y.Z，发布说明见 releases/vX.Y.Z-发布说明.md"。
8. **提交与 tag**：
   - 生成 `release: vX.Y.Z` 格式的提交：只暂存本会话工作范围内的文件，提交信息携带会话 ID；
   - 创建 tag `vX.Y.Z`（tag 说明摘录发布亮点）。**tag 操作不可撤销，必须先获得用户明确确认**；用户可拒绝打 tag，仅保留提交。
9. **收尾**：将花名册中本会话状态改为"已完成"；建议用户发布后执行 `/moma-test` 做冒烟回归，若发现缺陷则 `/moma-fix` 并出补丁版本（patch）。

## 发布说明模板

```markdown
# vX.Y.Z 发布说明

- **发布日期：** {{YYYY-MM-DD}}
- **会话 ID：** {{会话 ID}}
- **上一个版本：** {{vX.Y.Z-1 或"首个版本"}}

## 新增功能
- {{功能描述（CR-编号）}}

## 优化与调整
- {{优化描述（CR-编号）}}

## 缺陷修复
- {{修复描述（BUG-编号）}}

## 已知问题
- {{未关闭缺陷（BUG-编号，状态）}}

## 升级须知
{{破坏性变更、数据迁移、配置调整等；无则写"无"}}
```

此指令不修改业务逻辑代码；版本号变更、发布说明与 tag 是其全部产出。
