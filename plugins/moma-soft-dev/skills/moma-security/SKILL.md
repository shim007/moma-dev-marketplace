# /moma-security —— 安全审查

从代码、依赖、配置三个层面识别常见安全风险，与 `/moma-review` 的功能性评审互补。

> 共享约定见 `${CLAUDE_PLUGIN_ROOT}/skills/moma-soft-dev/references/common-conventions.md`。本文件中 `docs/` 路径均遵循共享约定的 `dev-docs/` 优先规则。

## 上下文范围

加载审查范围内的源码、依赖清单与配置文件 + `docs/07-测试策略.md`（4.2 安全测试清单，如存在）+ `docs/03-技术架构文档.md`（认证与数据流设计）+ `docs/02-产品需求文档.md`（个人数据处理相关需求）+ `docs/06-开发规约.md`（安全相关编码约定，如有）+ `docs/09-BUG记录.md`（如存在，用于登记严重问题）。不加载插件内置模板。

## 步骤

1. **登记**
   - 按"多会话并行规约"生成会话 ID，读取花名册 `<docs-root>/.moma-state/roster.md`（不存在则创建），登记本会话条目（指令 `/moma-security`、工作范围"只读审查 + security-reports/"、状态"进行中"）。
   - 本指令只读代码、只新增安全报告文件，不构成代码工作范围冲突，可与其他指令并行执行；无需 checkpoint 提交。
2. **确定审查范围**：用户指定的文件/目录；未指定时默认全项目，大项目优先覆盖处理认证、支付、个人数据的核心模块。
3. **文档预检**：按共享约定"文档预检规则"检查；文档缺失时不中止，按通用安全清单审查并在报告中注明"无文档约束可对照"。
4. **六维度审查**：
   1. **注入**：SQL 注入、命令注入、路径穿越、XSS、模板注入——重点检查未校验的输入进入危险调用（拼接 SQL、exec、文件路径拼接、innerHTML 等）；
   2. **认证与授权**：密码哈希算法（拒绝明文与弱哈希）、会话与令牌过期机制、越权访问（水平/垂直）、默认账号密码；
   3. **敏感信息**：硬编码的密钥/Token/密码（扫描常见密钥模式与高熵字符串）、日志中的敏感数据、明文传输；
   4. **依赖漏洞**：项目有对应工具时执行 `npm audit` / `pip-audit` / `mvn dependency-check` 等并汇总已知漏洞；无工具时提示用户手动核查；
   5. **配置安全**：调试开关、CORS 通配、危险默认值、错误堆栈对外暴露；
   6. **数据保护**：个人敏感数据脱敏、数据保留期限是否符合 02/06 文档的约束（如有）。
5. **问题分级**：每个问题包含位置、风险描述、修复建议。
   - **严重**：可直接利用（密钥泄露、可注入点、越权读写）——必须立即修复；
   - **高危**：利用条件有限但后果严重；
   - **中危**：纵深防御缺失；
   - **低危**：加固建议。
6. **写入安全报告**：在 `<docs-root>/security-reports/`（不存在则创建）新建 `security-YYYYMMDD-HHmm.md`，使用文末模板，并向用户输出问题清单摘要。
7. **缺陷登记（可选）**：严重级问题经用户确认后，按缺陷记录模板以追加式写入规则登记到 `docs/09-BUG记录.md`（级别"致命"或"严重"，状态"待修复"，条目含会话 ID；文件不存在则创建），建议优先 `/moma-fix`；若用户拒绝登记，在报告中注明"用户已知晓但未登记"，不强制写入。
8. **收尾**：将花名册中本会话状态改为"已完成"；建议将长期安全要求通过 `/moma-modify` 固化到 07-测试策略的常规检查项中。
