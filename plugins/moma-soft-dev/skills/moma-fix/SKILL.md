# /moma-fix —— 异常修复

定位并修复代码中的异常。

> 共享约定见 `${CLAUDE_PLUGIN_ROOT}/skills/moma-soft-dev/references/common-conventions.md`，编码通用约束必须严格遵守。

## 上下文范围

加载用户的异常描述 + `dev-docs/02-产品需求文档.md`（理解预期行为） + `dev-docs/03-技术架构文档.md`（理解技术实现） + `dev-docs/06-开发规约.md`（确保代码规范） + `dev-docs/07-测试策略.md`（缺陷记录模板） + 异常相关代码。不加载 01-项目概要（宏观信息不需要），不加载无关的 04/05 文档（除非异常与数据/接口直接相关）。

## 步骤

1. **文档预检、登记与检查点**
   - 按共享约定的"文档预检规则"检查：本指令适用**例外条款**——文档缺失不阻塞修复，告知用户后跳过依赖文档的步骤（约束核对、07 模板），继续定位与修复，缺陷记录使用下方内置模板，并建议事后 `/moma-sync` 补齐文档。
   - 按共享约定的"多会话并行规约"生成会话 ID，读取花名册 `<docs-root>/.moma-state/roster.md`（不存在则创建）：先初步定位异常涉及的文件，以其声明工作范围；若与其他"进行中"会话的工作范围重叠，拒绝直接执行并报告冲突，按共享约定"规则6：worktree 兜底隔离"提议迁移到独立 worktree 继续，获用户确认后在 worktree 内执行；若用户不接受或前置检查不满足，则调整本会话范围或等待对方完成。若无重叠，登记本会话条目（状态"进行中"）。
   - 若工作区存在未提交改动，先按规约生成 `checkpoint:` 提交。
2. 分析异常所在功能模块，定位可能原因，通过 plan 方式逐步修复，遵循 `⚠️ AI 约束`。修复过程中的提交只暂存本会话工作范围内的文件。修复后按共享约定"验证阶梯"完成自我验证。
3. 修复完成后输出问题原因说明。
4. 按照 `dev-docs/07-测试策略.md` 的 "6.2 缺陷记录模板" 格式，按追加式写入规则将 bug 追加到 `dev-docs/09-BUG记录.md`（编号取当前最大编号加 1，条目含会话 ID，**状态置为"已修复"**；文件不存在则创建）：

```markdown
### BUG-{{编号}}: {{缺陷标题}}
- **级别：** 致命/严重/一般/轻微
- **发现场景：** {{测试用例编号或描述}}
- **复现步骤：**
  1. ...
  2. ...
- **预期结果：**
- **实际结果：**
- **修复方案：**
- **状态：** 待修复/修复中/已修复/已验证
```

5. 如果项目有版本控制，生成 `bug: <修复简述>` 格式的提交：只暂存本会话工作范围内的文件，提交信息携带会话 ID。
6. 将花名册中本会话状态改为"已完成"，并提示：回归验证由 `/moma-test` 承担——回归通过后 BUG 状态按规则4的"状态流转例外"流转为"已验证"，不通过则改回"待修复"。
