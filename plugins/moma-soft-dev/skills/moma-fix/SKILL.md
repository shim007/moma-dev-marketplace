# /moma-fix —— 异常修复

定位并修复代码中的异常。

> 共享约定见 `../moma-soft-dev/references/common-conventions.md`，编码通用约束必须严格遵守。

## 上下文范围

加载用户的异常描述 + `docs/02-产品需求文档.md`（理解预期行为） + `docs/03-技术架构文档.md`（理解技术实现） + `docs/06-开发规约.md`（确保代码规范） + `docs/07-测试策略.md`（缺陷记录模板） + 异常相关代码。不加载 01-项目概要（宏观信息不需要），不加载无关的 04/05 文档（除非异常与数据/接口直接相关）。

## 步骤

1. 分析异常所在功能模块，定位可能原因，通过 plan 方式逐步修复，遵循 `⚠️ AI 约束`。
2. 修复完成后输出问题原因说明。
3. 按照 `docs/07-测试策略.md` 的 "6.2 缺陷记录模板" 格式，将 bug 记录到 `docs/09-BUG记录.md`（不存在则创建）：

```markdown
### BUG-{{编号}}: {{缺陷标题}}
- **级别：** 致命/严重/一般/轻微
- **发现场景：** {{测试用例编号或描述}}
- **复现步骤：**
  1. ...
  2. ...
- **预期结果：**
- **实际结果：**
- **修复方案：**
- **状态：** 待修复/修复中/已修复/已验证
```

4. 如果项目有版本控制，生成 `bug: <修复简述>` 格式的提交。
