# /moma-modify —— 需求调整

调整已有需求，同步更新文档和代码。执行流程遵循 `${CLAUDE_PLUGIN_ROOT}/skills/moma-soft-dev/references/change-workflow.md` 的通用变更流程，本文件只声明本指令区别于其他变更指令的判定点与高危规则。

> 共享约定见 `${CLAUDE_PLUGIN_ROOT}/skills/moma-soft-dev/references/common-conventions.md`，编码通用约束必须严格遵守。

## 上下文范围

加载用户输入 + `docs/01-项目概要.md` + `docs/02-产品需求文档.md` + 受影响的下游文档（03~07 中相关部分） + `docs/08-变更日志.md` + 与变更相关的现有代码。不加载模板文件，不加载无关文档章节和代码。

## 本指令判定点

- **变更类型判定：** 对**已有需求**的调整、收窄或删减——区别于 `/moma-new`（新增原需求没有的功能）与 `/moma-optimize`（细化行为边界、不改需求范围）。
- **删除型变更高危规则：** 调整涉及删除已有功能、接口、数据表/字段或外部依赖时：
  1. 执行前必须列出影响面清单（调用方、历史数据、下游文档），并获用户**明确确认**；
  2. 数据表/字段默认不做物理删除，优先软删除或迁移方案；确需物理删除时在 08 条目中单独记录数据处理方式；
  3. 在 08-变更日志中登记为独立 CR 条目，变更类型注明"需求变更（删除）"。

## 步骤

按 `change-workflow.md` 的步骤1~7 顺序执行，本指令的差异点：

- 步骤2 意图分析：识别用户输入中哪些**已有需求**需要调整；
- 涉及删除时，先执行上文"删除型变更高危规则"，再进入步骤3；
- 步骤6 提交前缀：`modify: <变更简述>`。
