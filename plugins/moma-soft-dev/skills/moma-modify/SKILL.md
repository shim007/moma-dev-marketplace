# /moma-modify —— 需求调整

调整已有需求，同步更新文档和代码。

> 共享约定见 `${CLAUDE_PLUGIN_ROOT}/skills/moma-soft-dev/references/common-conventions.md`，编码通用约束必须严格遵守。

## 上下文范围

加载用户输入 + `docs/01-项目概要.md` + `docs/02-产品需求文档.md` + 受影响的下游文档（03~07 中相关部分） + `docs/08-变更日志.md` + 与变更相关的现有代码。不加载模板文件，不加载无关文档章节和代码。

## 步骤

1. **登记与检查点**
   - 按共享约定的"多会话并行规约"生成会话 ID，读取花名册 `<docs-root>/.moma-state/roster.md`（不存在则创建）：工作范围声明为本次将更新的 01/02 及下游文档 + 将变更的代码文件；若代码文件与其他"进行中"会话的工作范围重叠，拒绝直接执行并报告冲突，按共享约定"规则6：worktree 兜底隔离"提议迁移到独立 worktree 继续，获用户确认后在 worktree 内执行；若用户不接受或前置检查不满足，则调整本会话范围或等待对方完成。若无重叠，登记本会话条目（状态"进行中"）。
   - 若工作区存在未提交改动，先按规约生成 `checkpoint:` 提交。
2. 结合 01 和 02 文档，分析用户输入中哪些需求需要调整。
3. 更新阶段1文档，并同步更新受影响的下游文档（03~07）。遵循"文档单写者"规则：写入每个文档前先重新读取确认，若发现被其他会话修改则基于最新内容重新规划；若有其他会话正在写文档，则拒绝文档写入并报告，可提议按"规则6：worktree 兜底隔离"迁移（剩余步骤在 worktree 内完成）或等待对方完成。如果下游文档已存在，必须逐一检查并更新；如果尚未生成则跳过。
4. 根据变更需求进行代码变更，遵循 `⚠️ AI 约束`。
5. 按追加式写入规则在 `docs/08-变更日志.md` 中记录本次变更（编号取当前最大编号加 1，条目含会话 ID；不存在则创建）。
6. 如果项目有版本控制，生成 `modify: <变更简述>` 格式的提交：只暂存本会话工作范围内的文件，提交信息携带会话 ID。
7. 将花名册中本会话状态改为"已完成"。
