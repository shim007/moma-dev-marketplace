# /moma-incident —— 事故应急

生产事故的应急处理流程：先止血控制影响面，再定位根因，最后修复与防复发。与 `/moma-fix` 的常态修复节奏不同——本指令以恢复服务为第一优先级。

> 共享约定见 `${CLAUDE_PLUGIN_ROOT}/skills/moma-soft-dev/references/common-conventions.md`。本文件中 `dev-docs/` 路径均遵循共享约定的文档存放规则。

## 上下文范围

加载用户的事故描述 + `dev-docs/03-技术架构文档.md`（部署形态与依赖）+ 事故相关代码与日志 + 近期变更记录（`dev-docs/08-变更日志.md`、自上一个 tag 以来的 git 提交）+ `dev-docs/09-BUG记录.md`（如存在，用于登记缺陷）。不加载无关文档；文档不是本指令的硬性依赖（见步骤1）。

## 步骤

1. **登记与检查点**
   - **紧急指令不被文档缺失阻塞**：文档缺失时告知用户后跳过依赖文档的步骤，继续应急处理。
   - **极端紧急（P0 且每秒扩大损失）时**：可先执行步骤3 中最稳妥的止血操作，随后立即补办本步登记；事后必须在花名册与 08 条目中注明"先止血后登记"及原因。
   - 按"多会话并行规约"生成会话 ID，读取花名册 `<docs-root>/.moma-state/roster.md`（不存在则创建）：先初步定位事故涉及的文件，以其声明工作范围。若与其他"进行中"会话的工作范围重叠，**事故应急优先**——向用户报告冲突会话，由用户选择让对方暂停，或获用户确认后本会话直接执行（在花名册备注"应急优先"），事后告知被冲突会话。若无重叠，登记本会话条目（状态"进行中"）。
   - 若工作区存在未提交改动，先按规则5生成 `checkpoint:` 提交。
2. **评估事故级别**：
   - **P0**：系统完全不可用 / 数据丢失或损坏 / 安全入侵；
   - **P1**：核心功能不可用；
   - **P2**：部分功能受损，存在替代方案。
   - 向用户报告评估结果与依据；P0 建议用户同步通知相关干系人。
3. **先止血（最高优先级）**：优先选择可逆、低风险的措施：
   - 回滚到上一个稳定版本（git revert 近期提交，或依据 `releases/` 发布记录回退部署版本）；
   - 通过开关/特性标志关闭可疑功能；限流或降级非核心依赖；
   - 影响生产环境的止血操作**必须获得用户明确确认**（除非用户已预先授权）；每一步止血操作记入事故时间线。
   - 止血变更是**最小临时变更**，不做正式修复。
4. **后定位**：结合日志、近期变更（自上一个 tag 以来的 git 提交与 08 CR 条目）、复现路径定位根因；无法立即确认时，按可能性列出候选原因与进一步排查计划，不臆断。
5. **写入事故记录**：在 `<docs-root>/incident-records/`（不存在则创建）新建 `incident-YYYYMMDD-HHmm.md`，使用文末模板。
6. **交接修复**：根因明确后建议用户执行 `/moma-fix` 进行正式修复（修复后由 `/moma-test` 回归验证）；本指令不做大规模修复。
7. **补齐流程登记**：
   - 按追加式写入规则在 `dev-docs/08-变更日志.md` 追加条目（变更类型注明"事故应急"，条目含会话 ID，引用事故记录文件；文件不存在则创建）；
   - 对应 BUG 按缺陷记录模板登记到 `dev-docs/09-BUG记录.md`（状态按实际：止血完成但未根治时为"修复中"；文件不存在则创建）；
   - 若应急止血偏离了任何文档约束，在 08 条目中补记说明。
8. **收尾**：将花名册中本会话状态改为"已完成"；给出防复发建议：补回归用例（`/moma-test`）、监控告警或开关控制（`/moma-modify`）、架构薄弱点加固（`/moma-optimize`）。

## 止血措施

## 后续改进
