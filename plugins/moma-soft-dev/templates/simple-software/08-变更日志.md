# 变更日志

> **定位：** 记录项目从启动到交付全过程中的所有重要变更，是项目可追溯性的保障。
> **生成时机：** 项目启动时创建，在整个开发过程中持续更新。
> **使用方式：** 每次对需求、设计、代码进行重大变更时，AI 或人工在此记录。AI 编码时如需偏离已确认的文档，必须先在此登记变更。

## 2. 变更规则

> **⚠️ AI 约束：以下任何一种情况发生时，必须先记录变更，再执行修改。不得先改代码后补记录。**

**必须记录变更的场景：**
- 需求新增、修改或删除
- 技术架构调整（如更换技术栈组件）
- 数据模型变更（新增/修改表或字段）
- API 接口变更（路径/参数/响应结构变化）
- 开发规约调整
- 重大缺陷修复

**变更审批流程：**
```
提出变更 → 影响评估 → [人工确认] → 更新相关文档 → 执行变更 → 验证
```

> **⚠️ AI 约束（多会话并行）：本文档只允许在末尾追加新条目，禁止修改、删除或重排已有条目。编号以当前最大 CR 编号加 1 生成，条目必须携带会话 ID（见 moma-soft-dev 共享约定的"多会话并行规约"）。**
